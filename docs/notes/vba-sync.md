# VBAの反映のImportの形

`vba_sync`（[API](../api.md#vba_sync段階1)）が依存する、遅延バインドの`VBComponents.Import`の振る舞いの記録です。
Importの文字コード、全置換、属性の保ち方は、[VBAの反映とマクロの実行](vba-run.md)にあります。
確かめた日は2026-11-03です。

## 版

- Windows 11 Pro 10.0.26300、.NET 10.0.14（x64）
- Microsoft 365 Excel 64-bit 16.0.20527.20112
- システムのANSIコードページ: 932
- Excelの設定: `AccessVBOM`は1、`VBAWarnings`は2
- 起動した場所: Claude Codeのデスクトップアプリの会話のシェル（Git Bash）から起動した`dotnet`

## 再現の手順

```powershell
dotnet run --project spikes\vba-sync
```

実験は、STAのスレッドから専用のExcelを1つ起動し、所有を確かめます（新しいPID、`EXCEL.EXE`、起動を求めた後の生成）。確かめられなければ、触らずに止まります。
ファイルの無い新しいブックに、一時フォルダへCP932で書いたモジュールのファイルをImportします。保存せずに閉じます。
取得したCOMのオブジェクトは、すべて解放します。

## 判定

### クラスのヘッダー

支持。拡張子が`.cls`でも、ヘッダーの無いファイルは標準モジュール（`Type`が1）になった。
`VERSION 1.0 CLASS`・`BEGIN`・`MultiUse = -1`・`END`の4行だけを足すと、クラスモジュール（`Type`が2）になった。ほかの`Attribute`の行は要らなかった。

### `VB_Name`

- `Attribute VB_Name`の無いファイルは、`Module1`・`Class1`のように番号の付いた名前になった。
- 先頭にコメントの行があっても、その後の`Attribute VB_Name`の名前になった。コメントは、コードの1行目に残った。

### 名前が既にある時

支持（例外にならない）。同じ名前のモジュールがあると、Importは名前に番号を付けて取り込んだ。

- `Sheet1`は`Sheet11`に、`ThisWorkbook`は`ThisWorkbook1`になった（シートとブックのモジュールと同じ名前）。
- 先に取り込んだ`Twice`と同じ名前は、`Twice1`になった。
- 標準・クラスモジュールをすべて`Remove`した後は、同じ名前の`Twice`を番号なしで取り込めた。

そのため、Importの後に、取り込んだモジュールの名前がソースの名前と同じかを確かめる必要があります。

### 不正な名前

- 31文字の名前は、そのまま取り込めた。
- 32文字の名前は、例外にならず`Module2`になった。
- 数字で始まる名前（`1Digit`）と予約語（`Option`）は、`COMException`（`0x800AC3D4`、「オブジェクト名が不正です」）になった。
- 日本語の名前（`日本語名`）は、取り込めた。

### そのほか

- 改行がLFだけのファイルも、取り込めた。
- 空のファイルは、`COMException`（`0x800AC365`、「ファイルにこれ以上データがありません」）になった。
- 保護していないVBAのプロジェクトの`Protection`は0だった。

## 未確認

- 保護したVBAのプロジェクトの`Protection`の値と、その時のImportと`Remove`の失敗の形。保護したプロジェクトは、VBEの画面でしか作れないため。

## 後始末とGit差分

- 実行の前と後で、EXCELのプロセスは0だった。`Quit`の後、プロセスは自ら終わった。
- 一時フォルダは、実行の最後に消した。
- Gitで管理するブックには触れていない。
- Gitの差分は、実験の追加と本書の追加だけです。
