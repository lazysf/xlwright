# 0003: 開発をInspector中心にし、開発用のExcel開始ツールを外す

- Status: Accepted
- Amends: 0002

## 背景

エージェントが作成・テスト・修正のループを自走するには、AIクライアントの再起動に依存せず、検証したビルドを確実に実行できる必要があります。
AIクライアントの登録先は通常の`bin`で、統合チェックの出力先とは別のビルドでした。
更新にはアプリの通常終了と再起動が必要でした。
MCPの開始ツールは実施済みの固定実験用で、T7以降の実験では追加していません。

## 決定

- AIクライアントのプロジェクト設定をリポジトリから外し、開発サーバーはInspectorから起動します。
- MCPのExcel開始ツールと、Spike0を子プロセスで動かすアダプターを削除します。開発モードは`dev_status`だけを公開します。
- Spikeの実Excel実験は、統合チェックを通過したビルドの固定コピーを、人がコンソールで起動します。
- アダプターが持っていた開始前の検査をSpike0へ移します。全Excel入口が共有ガードを確認・作成し、固定コピーの`manifest.json`を照合します。

本決定は開発用ツールだけに適用します。
製品のExcel操作は、これまでどおりMCPツールとして提供します。stdio接続基盤も維持します。

## 検討した代替案

- 接続先へ検証済みの成果物を昇格する案は、クライアントの再接続が残ります。Inspectorで足りる反復に対して、手順が増えます。
- Hotloadによる差替えは、開始ツールの応答後も続くExcel処理と競合します。[調査記録](../notes/mcp-reload-study.md)を参照してください。
- 開始ツールを基準に合わせて残す案は、人がコンソールで起動すると決めた後に使う経路がなく、保守だけが残ります。

## 影響

開始前の検査は、固定5入口ではアダプターだけが持っていました。ガードの検査はSpike0へ移したので、起動経路によらず働きます。
アダプターの「所有記録がcompleted以外なら拒否」は移していません。全実行が記録の遷移より前にガードを作り、正常終了の確認後だけ除去するので、ガードで代替します。
ガードがない時の所有記録の扱いは変えていないため、T12の次回開始の評価は残せます。
MCP経由でExcelを動かす経路は、製品ツールを実装するまでありません。
S13やR3のようにAIクライアントでの確認が必要な工程では、着手時に登録方法を決めます。
エージェントのシェルではCOM生成の拒否を、アプリのMCP経由では成功を観測しています。Inspector CLIから実Excelへ届くとは仮定しません。
