# 設計

本書は、[要件](requirements.md)の[仕組み](requirements.md#仕組み)をどの方式で満たすかを定めます。
「未確認」は、実機で確かめていない仮説です。確かめる段階と、成立しない時の扱いを、同じ箇所に書きます。
段階は[ロードマップ](../ROADMAP.md)のものです。各段階の最初に確かめる事項は、ロードマップから本書の該当箇所を指します。
ツールの名前と共通の規約は[API](api.md)にあります。

実装は、[ExcelMcp](https://github.com/sbroenne/mcp-server-excel)（sbroenne、.NET 10、MIT）の同じ対象のソースを読んで参考にし、xlwrightの方針で書きます。
ExcelMcpの次の形は、取り入れません。期限が切れても専用のExcelを終了させない形、記録と照合せずに同じユーザーのExcelを列挙して接続する形、PIDが取れない時にExcelが生きているとみなす形です。目標の3・4と、所有の確定の規則に反するためです。
著作権表示を置かないため、ソースを横に開いて書き写すことはしません。

## 構成

```text
Claude Codeの会話
  └─ MCP（stdio）
      └─ XlWright.McpServer
          └─ XlWright.Core（MCPに依存しない）
              └─ 専用のSTAスレッド
                  └─ 専用のExcel（EXCEL.EXE）
```

- 1つのサーバーが持つセッションは、最大1つです。ツールは`session_id`を引数に取りません。会話ごとにサーバーが1つ付くなら、セッションを区別する必要が無いためです。
- 確認済み（段階0、[記録](notes/dev-plugin-loading.md)）: Claude Codeのデスクトップアプリは、プラグインのサーバーを会話ごとに起動した。
- Excelのオブジェクトは、専用のSTAスレッドの中でだけ作り、使い、解放します。スレッドの外へ渡しません。
- 状態の照会はCOMを使わず、サーバーが持つ情報から返します。STAが塞がっていても答えるためです。
- 確認済み（段階1、[記録](notes/sta-com.md)）: .NETのSTAから呼ぶと、Excelは再計算の間の呼出しに`RETRYLATER`を返し、メッセージフィルターの再試行で通った。フィルターが無いと`RPC_E_CALL_REJECTED`で失敗した。起動の直後の`SERVERCALL_REJECTED`は、この端末では起きなかった。ExcelMcpは、管理された端末で起動中に出るサインインのダイアログを理由に、REJECTEDを再試行しています。返る端末が見つかった時は、開始に限って再試行するかを人が判断します。
- 確認済み（段階1、[記録](notes/workbook-save-open.md)）: 小さなブックでは、保存・Closeは0.2秒以内に戻り、`RETRYLATER`は起きなかった。大きなブックでは確かめていません。遅延した戻りが起きた時は、[期限](#期限と大きさの上限)の規則で扱います。

## アプリのフォルダ

アプリのフォルダは、次の規約で構成します。
設定ファイルを持たないのは、キーと検証を保守せずに済み、`.xlsx`から`.xlsm`へ変えた時に設定を書き換えずに済むためです。

```text
apps/sales/                  アプリのフォルダ（リポジトリの中。リポジトリの直下でもよい）
  Sales.xlsm                 主ブック。直下のブックは1つまで
  src/
    modules/*.bas            標準モジュール
    classes/*.cls            クラスモジュール
    workbook/<CodeName>.cls  シートとブックのモジュール
  tests/*.bas, tests/*.cls   テストのモジュール。テストの写しにだけ取り込む
  data/ など                 参照用・テスト用のブックとCSV。名前は自由
  .xlwright/                 実行時の状態。Gitの管理から外す
    session.json             排他と所有記録
    logs/<session-id>.jsonl  診断の記録
    results/<id>.json        応答に収まらない実行の結果
    test/<run-id>/           テストの写し
    sync/<id>/               反映のために変換したモジュールのファイル。反映の後に消す
    extract/<id>/            取り出しのためのブックの写し。取り出した後に消す
```

- 開始では、アプリのフォルダだけを渡します。主ブックは、直下にある`.xlsm`か`.xlsx`です。2つ以上なら、開始で拒否します。
- 直下にブックが無い時は、主ブックの無いセッションを始めます。このセッションでは、`workbook_create`・`session_status`・`session_end`だけを受け付けます。`workbook_create`は、専用のExcelで新しいブックを作り、直下に保存します。作ったブックが主ブックになります。この形は、`workbook_create`と一緒に段階4で作ります。段階3までは、直下にブックが無ければ開始で拒否します。
- 主ブックを数える時は、`~$`で始まるファイルと、隠しファイルを除きます。Excelは、編集で開いたブックと同じフォルダに、`~$`で始まる所有者ファイルを作るためです。
- アプリのフォルダは、入れ子にしません。ほかのアプリのフォルダの中や上に置くと、ほかのアプリのブックも「アプリのフォルダの中のブック」として扱われるためです。規約からは`data/`のようなサブフォルダと見分けられないため、xlwrightは検出しません。この規則は、プラグインのスキルでAIエージェントへ渡します。
- `.xlsx`から`.xlsm`へ変えた後、AIエージェントが旧い`.xlsx`をGitで消すと、主ブックが切り替わります。
- ほかのブック（参照用やテストのデータ）は、サブフォルダに置きます。
- 拡張子とフォルダが食い違うファイルと、`src/`・`tests/`の下の入れ子のフォルダは、反映の前に拒否します。
- `src/`・`tests/`の下の`.`で始まるファイル（`.gitkeep`など）は、反映でも検査でも数えずに飛ばします（人が承認、2026-11-04）。空のフォルダをGitに残すためです。
- `src/workbook/`のファイル名は、シートとブックのCodeNameです。対応するモジュールがブックに無ければ、反映の前に拒否します。
- 排他と実行時の状態の単位は、アプリのフォルダです。1つのアプリの主ブックは1つなので、目標の5の「同じ主ブック」は、アプリのフォルダで判定できます。
- テストの写しもアプリのフォルダの中に置くため、開くブックをアプリのフォルダの中に限る規則が、例外なしで成り立ちます。サーバーが止まった後も、写しは「アプリのフォルダの中のブック」として識別できます。
- xlwrightが保存するのは主ブックだけです。テストの写しは保存せずに捨てます。
- サーバーのインストール先には、利用者のブック・設定・記録を置きません。`${CLAUDE_PLUGIN_ROOT}`はプラグインの版ごとに変わるためです（[プラグインの読み込み](https://code.claude.com/docs/en/plugins/loading.md)）。

### パスの制限

- アプリのフォルダは、サーバーの引数`--project`が指すリポジトリの中に限ります。
- フォルダの中かどうかは、正規化した完全なパスを、末尾の区切り文字まで含めた前方一致で比べます。大文字と小文字は区別しません。`apps\sales`と`apps\sales2`を取り違えないためです。
- 利用する版のプラグインは`--project`に`${CLAUDE_PROJECT_DIR}`を渡します。開発版は、このリポジトリの完全なパスを渡します（[サーバーとビルドとプラグイン](#サーバーとビルドとプラグイン)）。既定の値を付けた`${CLAUDE_PROJECT_DIR:-.}`は、プラグインの設定では展開されず`.`になりました。サーバーは、相対パスを作業ディレクトリを基準に解決します。
- 確認済み（段階0、[記録](notes/dev-plugin-loading.md)）: プラグインのサーバーで、`${CLAUDE_PROJECT_DIR}`はリポジトリの完全なパスに展開された。
- UNC、デバイスパス（`\\?\`・`\\.\`で始まるパス）、ネットワークドライブ（`DriveType.Network`）は、パスに触れる前に拒否します（[利用の前提](requirements.md#利用の前提)）。
- 未確認（段階2）: 同期しているフォルダ（OneDriveなど）のブックで、`Workbook.FullName`がローカルのパスを返すか。成立しない時は、同期フォルダの中のアプリを開始で拒否する案を人が判断し、利用の前提に書きます。

## 実行時の状態と所有記録

この節の排他と所有記録のファイルと、次の開始での片付けは、段階2で作りました。

- [完了にする条件](#完了にする条件)の、OSで終了を確かめることと、プロセスのハンドルを持ち続けることは、段階1にも当てはまります。
- [状態と結果不明](#状態と結果不明)のCOMの切断の扱いを作るまでは、専用のExcelを残して止まる時は、期限切れで終了させる時を除き、どの経路でもそのExcelに触りません。COMが切れてプロセスが残る時も、照合して終了させずに止まります。
- この時は、PID、生成時刻、理由を、応答の`data`と診断の記録に出して止まります。次の開始の片付けが確かめられない時に備えて、応答には、人がそのExcelを確かめて閉じる手順を含めます。

- サーバーは、セッションの間、`<アプリ>/.xlwright/session.json`を`FileShare.None`で開いたまま持ちます。
- このファイルを開けなければ、別の会話がそのアプリを使用中です（目標の5）。
- サーバーが強制終了されると、OSがファイルを閉じます。
- サーバーは、セッションのExcelへのCOMの参照をすべて解放し、以後そのExcelに触れないと決めてから、排他を外します。保留中のCOM呼出しが残る間は、排他を外しません。
- そのため、排他を取れたことは、そのアプリのセッションを持つサーバーが無く、記録したExcelをどの会話も使っていないことを示します。
- 会話を閉じた後の片付けは、次の開始で行います。サーバーの終了時の後始末には頼りません。
- 未確認（段階2）: Claude Codeが会話を閉じた時に、標準入力を閉じてから、どれだけの時間でサーバーを終了させるか。後始末が間に合う長さなら、終了時の後始末を加えるかを人が判断します。
- 確認済み（段階2、[記録](notes/stage2-cleanup.md)）: デスクトップアプリで会話をアーカイブすると、結果が戻った直後（1秒以内）の照会で、その会話のサーバーは無かった。専用のExcelは残り、次の開始の片付けが終了させた。片付けには約10秒かかるため、終了時の後始末は加えません（人の判断、2026-11-04）。ほかの閉じ方は確かめていません。
- 標準入力が閉じた時は、Excelと所有記録に触れず、排他のハンドルも明示的に閉じません。サーバーが終わった時に、OSが排他を外します。保留中のCOM呼出しが残ったまま、動いているサーバーが排他を外さないためです。

### 所有記録の形式

同じファイルに、UTF-8（BOM無し）のJSONで所有記録を書きます。

```json
{
  "version": 1,
  "state": "owned",
  "marked_at_utc": "2026-11-02T01:23:45.6789012Z",
  "workbook": "Sales.xlsm",
  "process": { "pid": 12345, "started_at_utc": "2026-11-02T01:23:46.1234567Z", "name": "EXCEL" }
}
```

- `state`は`starting`（起動前の印）、`owned`（所有の確定）、`completed`（完了）のどれかです。
- `marked_at_utc`は、起動前の印を書いた時刻です。`process`は`owned`だけが持ちます。
- 時刻は、.NETのラウンドトリップ形式のUTCです。`process`の3項目は、PIDの再利用と取り違えないために照合します。
- 更新は、開いたままのハンドルで、書込み、長さの確定、`Flush(true)`、読み戻しと照合の順に行います。照合が済むまで、次のExcelの操作へ進みません。
- 厳密なJSONとして読みます。コメント、末尾のカンマ、重複したキー、未知のキーは不正とします。
- ファイルが無い時だけ、新しく作ります。新しく作れたファイルだけを初回とみなします。ファイルが在ることを確かめただけでは、初回とみなしません。
- 初回は、作った直後に`completed`を書きます。
- 既にあったファイルは、記録を確かめ、残った専用のExcelがあれば片付けた後に、`completed`を書きます。
- 既にある空のファイル、形式が不正な記録、読めない記録は、開始で拒否し、止まって知らせます。読取りの失敗を、プロセスの不在に置き換えません。
- 更新は先頭から書き、書く前にファイルを切り詰めません。そのため、空のファイルは、作ってから`completed`を書くまでの間に止まった時にだけ残ります。この時、専用のExcelはまだ起動していません。
- 人は、空のファイルを消してから開始し直します。セッションを持つサーバーがファイルを開いている間は、消せません（[人への引継ぎ](#人への引継ぎ)）。
- この手順は、原子的な更新や電源断の後の保持を保証しません。

### 完了にする条件

- OSでプロセスの終了を確かめるまで、所有記録を完了にしません。Quitの成功やCOMの参照の解放だけでは、終了とみなしません。
- 同一性の照合と終了は、同じプロセスのハンドルで行います。このセッションのExcelのハンドルは、所有を確定した時に開き、セッションの間持ち続けます。PIDで開き直すと、その間にPIDが再利用され、別のプロセスを終えるおそれがあるためです。
- 終了を確かめられない時は、所有記録を`owned`のまま残して排他を外し、止まって知らせます。次の開始の片付けが引き継ぎます。保留中のCOM呼出しが残る時は、[状態と結果不明](#状態と結果不明)のとおり排他を外しません。
- 起動前の印だけが残っている時は、`marked_at_utc`より後に生成されたEXCELのプロセスのうち、コマンドラインに`/automation`を含むもの（COMから起動されたもの）を数えます。コマンドラインを読めないプロセスも数えます。1つも無ければ、完了にして進みます。1つでもあれば、止まって知らせます。

## 開始の順序

1. [パスの制限](#パスの制限)を確かめます。直下のブックが1つ以下であることを確かめます。
2. アプリの排他を取ります。取れなければ、使用中と知らせて止まります（目標の5）。
3. 所有記録を読みます。残った専用のExcelがあれば、[片付け](#残った専用のexcelの片付け)ます。片付けられなければ止まります。残りが無いと確かめた後、`.xlwright/test/`に残ったテストの写しと、`.xlwright/results/`の前のセッションの結果を消します。
4. 主ブックのファイルを、書込みのアクセスで一瞬開きます。ほかのプログラムの読み取りと書込みは許します。共有違反なら、ほかのプログラム（日常のExcelなど）が編集できる状態で開いているため、閉じるよう知らせて止まります（目標の4）。ファイルの属性が読み取り専用なら、そう知らせて止まります。
5. 起動前の印を書き、専用のExcelを起動し、所有を確定します。
6. 主ブックを開きます。開いたブックの`ReadOnly`が真なら、閉じるよう知らせて止まります。

- 1〜6を作りました。3の`.xlwright/test/`の削除は、テストの写しを作る段階3で加えます。
- 直下にブックが無い時は、4と6を飛ばします。
- 2で排他を取れているため、4と6で止まる原因は、別の会話ではありません。
- 6で止まる時は、起動した専用のExcelを[終了](#終了)の2〜5で終えます。
- 確認済み（段階2、[記録](notes/main-workbook-share.md)）: ほかのExcelが主ブックを編集で開いている時、4は`0x80070020`の共有違反になった。読み取り専用で開いている時と、どのExcelも開いていない時は、開けた。ほかのExcelには、所有を確かめた非表示の専用のExcelを使った。6で開くと、`DisplayAlerts`が偽の時は止まらずに`ReadOnly`が真になった。

### 所有の確定

開始の5で、起動したExcelを自分のものと確定する条件です。

- 起動したExcelの`Hwnd`から、`GetWindowThreadProcessId`でPIDを引きます。
- そのPIDのプロセスの名前が`EXCEL`で、`marked_at_utc`より後に生成され、コマンドラインに`/automation`を含む時に限り、自分のものとします。PID、生成時刻、名前を、`owned`の記録に書きます。
- 確かめられない時は、起動したExcelに触らず、所有記録を`starting`のまま残して止まり、知らせます。照合できる記録が無いExcelには、終了させる根拠が無いためです。
- `owned`を書く前に失敗した時と、開始の期限が切れた時も、同じく止まります。保留中のCOM呼出しが残る時は、[状態と結果不明](#状態と結果不明)のとおり排他を外しません。
- 次の開始は、[起動前の印だけが残っている時](#完了にする条件)の規則で扱います。
- 段階1では、起動を求めた時刻を`marked_at_utc`の代わりに使い、記録はサーバーの中だけで持ちます。
- 確認済み（段階1、[記録](notes/sta-com.md)）: COMから起動したEXCELのコマンドラインは`/automation -Embedding`を含んだ。コマンドラインは、`PROCESS_QUERY_LIMITED_INFORMATION`で開いたハンドルから`NtQueryInformationProcess`で読めた。

## 残った専用のExcelの片付け

前のセッションの専用のExcelが残っている時に、次の開始で行います（目標の3）。段階2で作りました。

1. 排他を取れていることを前提にします。これで、記録したExcelをどの会話も使っていないことが分かります（[実行時の状態と所有記録](#実行時の状態と所有記録)）。
2. 記録の同一性を、OSのプロセスと照合します。プロセスが無ければ、記録を完了にして進みます。一致したプロセスのコマンドラインに`/automation`が無い時と、コマンドラインを読めない時は、触らずに止まります（人の判断、2026-11-04）。記録が書き換えられた時に、日常のExcelを終了させないためです。
3. 一致したプロセスのウィンドウから、COMでExcelに接続します。接続したExcelの`Hwnd`のプロセスも、記録と照合します。
4. 開いているブックが、すべてアプリのフォルダの中にあることを確かめます。Protected Viewで開いたブックは`Workbooks`に入らないため（[Microsoftの説明](https://learn.microsoft.com/en-us/office/vba/api/excel.protectedviewwindow.workbook)）、`ProtectedViewWindows`も照会します。
5. 確かめられたら、ブックを保存せずに閉じ、[終了](#終了)の3〜5で終えます。

- 4で、パスの無いブック（保存していない新しいブック）があれば、確かめられないとします。表示要求のコマンドで人へ見せたExcelでは、人が新しいブックを作れるためです。
- どれか1つでも確かめられない時は、そのExcelに触らず、止まって知らせます（[人への引継ぎ](#人への引継ぎ)）。ブックのウィンドウが無い時の扱いは、下にあります。
- 照合を終える前に開始の期限が切れた時も、残ったExcelに触らず、止まって知らせます。期限切れで終了させてよいのは、このセッションで所有を確定した専用のExcelだけです（[状態と結果不明](#状態と結果不明)）。
- 照合を終えた後に、閉じる操作やQuitが期限内に終わらない時は、同一性を照合して終了させます。開いているブックがアプリのフォルダの中だけだと、確かめ終えているためです。
- 確認済み（段階2、[記録](notes/leftover-excel.md)）: COMで起動した専用のExcelは、起動したプロセスの強制終了の後も残った。ブックの無いExcelは、10分経っても自ら終わらなかった。
- 確認済み（段階2、[記録](notes/leftover-excel.md)）: ブックのある非表示の残ったExcelには、`EXCEL7`のウィンドウからCOMで接続できた。`XLMAIN`からは接続できなかった。接続してブックを閉じ、Quitした後も、プロセスは約12分残った。そのため、5で終える時は、[終了](#終了)の4のとおり、期限を過ぎたら同一性を照合して終了させます。
- 確認済み（段階2、[記録](notes/leftover-excel.md)）: ブックの無い残ったExcelには、ウィンドウから接続できなかった。
- そのため、3で、一致したプロセスに`EXCEL7`のウィンドウが無い時は、接続せずに、同一性を照合してから終了させ、[終了](#終了)の5で終えます（人の判断、2026-11-04）。1と2で、記録したExcelをどの会話も使っていないことと、同一性を確かめているためです。ブックのウィンドウが無いため、閉じて失う作業もありません。`session_end`の途中でサーバーが強制終了された時など、ブックを閉じた後のExcelが残る場合を、人なしで片付けるためです。
- 確認済み（段階2、[記録](notes/leftover-excel.md)）: 非表示にしたブックのウィンドウにも、Protected Viewのウィンドウにも、`EXCEL7`があった。そのため、`EXCEL7`が無いことで、ブックのウィンドウが無いと見分けます。Protected Viewの`EXCEL7`からは、記録と照合できる`Application`を得られなかった。そのExcelは、3の照合ができないため、確かめられないとして止まります。
- 確認済み（段階2、[記録](notes/leftover-excel.md)）: 終わらないマクロを実行中の残ったExcelでは、`AccessibleObjectFromWindow`が10秒では戻らなかった。後から10〜30秒で`0x80004005`を返した。呼出しそのものには期限を渡せないため、照会だけのための使い捨てのSTAを立てて照会し、期限で見切ります。この形で10秒で見切れた。そのSTAで得たCOMのオブジェクトは、そのSTAの外へ渡しません。見切った呼出しは、保留中のCOM呼出しとして扱います。後から戻っても、片付けの続きは行いません。
- 確認済み（段階2、[記録](notes/leftover-excel.md)）: ブックを開いた専用のExcelを強制終了した後、`~$`で始まる所有者ファイルは残らなかった。次に新しい専用のExcelで主ブックを開くと、`ReadOnly`は偽で、開く操作は止まらずに戻った。そのため、利用の前提の`.gitignore`に`~$*`を加えません。
- 確認済み（段階2、[記録](notes/leftover-excel.md#変更した後の強制終了と自動回復2026-11-04)）: 非表示の専用のExcelでブックを変更し、自動回復の間隔（既定の10分）を過ぎてから強制終了した。自動回復の記録は作られず、次に新しい専用のExcelで開くと、`ReadOnly`は偽で、元のブックだけが開いた。自動回復が記録を作る条件は確かめていません。
- 確認済み（段階2、[記録](notes/main-workbook-share.md)）: 専用のExcelが主ブックを編集で開いている間に、ほかの専用のExcelで`ReadOnly`を真にして開けた。
- 確認済み（段階2、[記録](notes/stage2-scenarios.md)）: 専用のExcelが主ブックを開いている間に、人がエクスプローラーから日常のExcelで開くと、「使用中のファイル」のダイアログが出た。「読み取り専用」で開いて、中身を見られた。残った専用のExcelを、人が読み取り専用で開いたまま、次の開始が片付けた。

## 終了

1. 指定された時は、主ブックを保存します。
2. 開いているブックが、アプリのフォルダの中だけであることを照合します。`ProtectedViewWindows`も照会します。ほかのブックがあれば、終了せずに止まります。
3. ブックを閉じ、Excelに終了を求めます。
4. [期限](#期限と大きさの上限)内にプロセスが終わらなければ、同一性を照合してから終了させます。
5. プロセスの終了を確かめてから、所有記録を完了にし、排他を外します。

- 2では、パスの無いブック（保存していない新しいブック）を、保存せずに閉じてよいものとします。非表示の専用のExcelで新しいブックを作れるのは、このセッションのマクロだけだからです。
- 4で期限を設けるのは、原因によらず、報告の時点で専用のExcelを残さないためです（目標の3）。原因は追いません。
- 2で止まる時は、所有記録を`owned`のまま残して排他を外し、セッションを閉じて知らせます。人が[引継ぎ](#人への引継ぎ)の手順でExcelを確かめられるようにするためです。次の開始の片付けが、あらためて照合します。
- 2で止まる時と、4・5で終了を確かめられない時は、`session_end`は`CONFLICT`を返し、`data`に保存の結果と引継ぎの情報を入れます。結果が分かっているため、`STATE_UNKNOWN`は使いません。
- 報告の前にセッションを終えることは、プラグインのスキルでAIエージェントへの手順として渡します（[サーバーとビルドとプラグイン](#サーバーとビルドとプラグイン)）。
- 確認済み（段階1、[記録](notes/sta-com.md)）: ブックを開いていない時、Quitは2 ms以内に戻り、プロセスは2.2〜2.7秒で終わった。
- 確認済み（段階1、[記録](notes/sta-com.md)）: Excelから取得したオブジェクトを解放せずに残すと、Quitの後75秒経ってもプロセスが終わらなかった。GCを呼んでも変わらなかった。そのため、Coreは、中間のオブジェクトも含め、取得したCOMのオブジェクトをすべて明示して解放します。
- 確認済み（段階1、[記録](notes/workbook-save-open.md)）: ブックを保存して閉じた後も、プロセスはQuitから2.3〜2.6秒で終わった。期限の75秒は、ExcelMcpが1分を超える例を挙げているため、初期値のままにします。

## 状態と結果不明

- 公開する状態は`closed`と`ready`です。実行中は`busy`で表します。
- 期限切れの時は、このセッションで所有を確定した専用のExcelを、同一性を照合して終了させ、`closed`にして`STATE_UNKNOWN`を返します。開いているブックの照合は行いません。要件の目標の3は、実行時間の上限を過ぎた時に、今の会話が使う専用のExcelを、応答しなくても終了してよいとしています。[期限の表](#期限と大きさの上限)の期限は、どれもこの「実行時間の上限」に当たるとします。
- 結果不明の後に、以後の操作を拒否して人の復旧を待つ形（状態を1つ増やす形）は採りません。異常時もAIエージェントが片付けて作業を続ける、という目標と合わないためです。
- 所有を確定した後のCOMの切断では、プロセスが無ければ、所有記録を完了にして`closed`にします。プロセスが残っていれば、[片付け](#残った専用のexcelの片付け)の2〜5と同じ照合を通してから終えます。照合できなければ、[完了にする条件](#完了にする条件)のとおり止まって知らせます。どちらも`STATE_UNKNOWN`を返します。
- 所有を確定した後に、xlwright自身の失敗で専用のExcelの状態が分からなくなった時は、[終了](#終了)の2〜5で終えます。2を行えなければ、所有記録を`owned`のまま残して排他を外し、止まって知らせます。保留中のCOM呼出しが残る時は、排他を外しません。どちらも`STATE_UNKNOWN`を返します。
- 所有を確定する前の失敗・切断・期限切れは、[所有の確定](#所有の確定)の規則だけに従います。
- `STATE_UNKNOWN`の応答は、専用のExcelを終えたか、残して止まったか、このサーバーで開始し直せるかを、区別して返します（[API](api.md#成功と失敗)）。AIエージェントが、残っているのに片付いたと報告しないためです。
- 結果不明の要求は、自動で再送しません。AIエージェントが開始し直して作業を続ける条件は、[API](api.md#成功と失敗)にあります。
- 保存の途中で終了させると、主ブックのファイルが保存の前と後のどちらの内容かは分かりません。
- 保留中のCOM呼出しが残る時は、排他を外さず、セッションを閉じて知らせます。このサーバーでは新しいセッションを始めません。古い呼出しが、後から次のセッションの状態や所有記録を書き換えないためです。
- この時は、この会話を閉じてから、新しい会話で開始するよう求めます。会話を閉じるとサーバーが終わり、OSが排他を外します。次の開始の片付けが、残ったExcelを扱います。
- 明確な失敗（入力の不正、Excelが返したエラー）では、`ready`のまま失敗を返します。部分的に変更した時は、分かる範囲の処理済みの部分を返し、成功とは報告しません。
- 確認済み（段階1、[記録](notes/sta-com.md)）: `Application.Wait`の呼出しの途中で専用のExcelを終了させると、呼出しは約20 msで`RPC_S_CALL_FAILED`で戻った。
- 確認済み（段階1、[記録](notes/vba-run.md)）: 終わらないマクロの実行中や、マクロがダイアログで止まった時に終了させても、呼出しは`RPC_S_CALL_FAILED`で戻った。

## 期限と大きさの上限

どれも初期値です。段階1と段階2の実測で決めます。

| 対象 | 期限 |
| --- | --- |
| セルなどの同期の操作。終了の照合、Close、Quitの呼出し | 30秒 |
| 開始、保存 | 各120秒 |
| Quitの後の終了待ち | 75秒。過ぎたら終了させる |
| 片付けでのQuitの後の終了待ち | 10秒。過ぎたら終了させる（人の判断、2026-11-04） |
| 終了させた後、プロセスの終了を確かめる待ち | 5秒。過ぎたら、終了を確かめられないとみなす（[完了にする条件](#完了にする条件)） |
| 終了させた後、保留中のCOM呼出しが戻るのを待つ | 10秒。過ぎたら、保留中の呼出しが残るとみなす |
| マクロとテストの実行 | 既定300秒。指定で1〜1200秒。テストは1回の呼出しの全体で測る |

- 経過時間は単調時計で測ります。
- Quitの後の終了待ちの75秒と、終了させた後の確認の5秒は、ExcelMcpの`ProcessTerminationPolicy.cs`の値です。Quitが戻った後、自然な終了に1分を超えることがある、とされています。
- 片付けでのQuitの後の終了待ちを短くするのは、残った専用のExcelが、Quitの後に75秒以内に終わったことが無いためです（[記録](notes/leftover-excel.md)、[記録](notes/stage2-cleanup.md)）。75秒を待つと、開始の期限の120秒のうち、その後の起動と主ブックを開く操作に残るのが約45秒になります。照合を終えているため、待ちを短くしても失う作業はありません。
- Quitの後の終了待ちは、開始の中（片付けと、開始の6で止まって終える時）では、開始の期限の残りで打ち切ります。片付けでこの待ちが切れた時は、照合を終えているため、そこで終了させます。開始の中以外（`session_end`、COMの切断、xlwright自身の失敗など）では、75秒を待ちます。
- 終了させた後の2つの待ちは、操作の期限が切れていても、表の時間を待ちます。打ち切ると、毎回「終了を確かめられない」で止まるためです。
- `RETRYLATER`（Excelが呼出しを断った）だけを、操作の期限の中で合計10秒まで再試行します。受け付けられた呼出しの失敗・無応答・切断と、`SERVERCALL_REJECTED`は再試行しません。
- 再試行は、専用のSTAに登録するOLEのメッセージフィルターで行います。この方式が実Excelで働くことは、確かめました（[構成](#構成)）。
- 実行の上限を1200秒までにするのは、Claude Codeがstdioのサーバーの呼出しを、30分応答が無いと打ち切るためです（[MCP](https://code.claude.com/docs/en/mcp.md)）。
- 応答の大きさの上限は、[API](api.md#成功と失敗)にあります。Claude Codeがツールの結果を既定で25,000トークンに制限するためです（[MCP](https://code.claude.com/docs/en/mcp.md)）。
- 本文は、ASCII以外の文字をescapeしません。escapeした本文で数えると日本語の1文字が6文字になり、会話に届く文字数と上限が食い違うためです。escapeしていた版でも、成功の応答の日本語はescapeされずに会話に届きました（[記録](notes/response-size.md)）。
- 確認済み（段階1、[記録](notes/response-size.md)）: ひらがな19,600文字を含む`range_read`の応答は、Claude Codeに打ち切られずに会話に届いた。そのため、上限は20,000文字のままにします。トークンの数は測っていません。

## マクロの実行

- `macro_run`は、マクロが終わるか上限を過ぎるまで応答を待ちます。受付のIDと状態の照会は作りません。Claude Codeは長い呼出しを待てるためです。2分を超えた呼出しは会話のバックグラウンドの作業へ移り、30分の無応答で打ち切られます（[MCP](https://code.claude.com/docs/en/mcp.md)）。
- 実行中も、`session_status`はCOMを使わずに、`busy`と経過時間を返します。ほかの操作は待たせずに拒否します。
- 確認済み（段階1、実Excelの結合テスト`RunsMacrosAndReportsErrorsStatusAndADialog`）: 製品のサーバーで、3秒かかるマクロの実行中に、同じサーバーへMCPのクライアントから送った`session_status`が、`busy`の真と`operation`の`macro_run`を返した。Claude Codeの会話のAIエージェントが、実行中に`session_status`を送れるかは確かめていない。
- 実行の前に、毎回`src/`を主ブックへ[反映](#vbaの反映)します。古いコードを実行させないためです。
- 呼出しは、主ブックの名前で修飾した`Application.Run`で行います。
- 確認済み（段階1、[記録](notes/vba-run.md)）: 主ブックの名前で修飾した`Application.Run`で、主ブックのマクロを呼べた。整数と日本語の文字列の引数と戻り値を受け渡せた。開いていないブックで修飾した名前では、Excelは既定のフォルダからそのブックを開こうとした。
- そのため、`macro_run`が受け取るマクロの名前は`<モジュール>.<プロシージャ>`の形に限り、ブックの修飾（`!`・`'`・`[`・パスの区切り）を含む名前は拒否します。修飾は、xlwrightが主ブックの名前で付けます。
- 確認済み（段階1、[記録](notes/vba-run.md)）: 捕捉されない実行時エラーとコンパイルエラーは、COMの例外として返らず、ダイアログで止まった。非表示の専用のExcelでも、ダイアログ（コンパイルエラーではVBEのウィンドウも）は人の画面に表示された。終了させると、呼出しは`RPC_S_CALL_FAILED`で戻った。
- ダイアログで止まった時は、上限で終了させます。実行時エラーは、加えて、マクロを名前で直接呼ぶ関数を実行ごとに作り、その関数の`On Error`で捕まえて返します（下の「実行ごとに作るモジュール」）。コンパイルエラーは、この関数では捕まえられません。
- 確認済み（段階1、[記録](notes/macro-run.md)）: マクロの名前を受け取って`Application.Run`で呼ぶ関数では、呼んだマクロの実行時エラーを`On Error`で捕まえられず、ダイアログで止まった。生成したモジュールから名前で直接呼ぶと、実行時エラーと`Err.Raise`の番号・説明・発生元を捕まえられた。引数の数が宣言と合わない時は、コンパイルエラーのダイアログで止まった。この時は、ダイアログの見張りで`DIALOG`を返します（人が判断）。
- そのため、マクロの実行中は、専用のExcelのダイアログを短い間隔で見張ります。ダイアログを見つけたら、その文字を読み、上限を待たずに終了させ、読んだ文字を応答に返します（人が判断。見分け方と読み方は[失敗の返し方と記録](#失敗の返し方と記録)）。コンパイルエラーのほか、捕まえ損ねた実行時エラーやMsgBoxで止まった時も、何が起きたかを返すためです。

### 実行ごとに作るモジュール

- `macro_run`は、反映の後、標準モジュール`XlWrightCall`を`VBComponents.Add`と`AddFromString`で作ります。中身は、受け取った引数を括弧で囲んでマクロを名前で直接呼び、`On Error`で捕まえて`Err.Number`・`Err.Description`・`Err.Source`を返す関数だけです。実行の後、モジュールを`Remove`します。
- 呼ぶ前に、VBIDEでマクロの有無を見分けます。モジュールが無い、標準モジュールでない、手続きが無い（`ProcBodyLine`が失敗する）、宣言の行が`Private`で始まる時は、`MACRO_NOT_FOUND`です。宣言の行から、`Sub`か`Function`かを決めます。
- 戻り値は、`XlWright.bas`の関数に`ByVal`の`Variant`で渡し、オブジェクト・配列・`CVErr`の値・日付を、型の名前に変えます。オブジェクトの既定のメンバーを読まないためと、`CVErr`の値が.NETでは`Long`と同じ`Int32`で届くためです（[記録](notes/macro-run.md)）。
- `XlWrightCall`は、ソースに置きません。実行の間だけ主ブックにあり、全置換の反映には含まれません。ソースに`XlWrightCall`という名前のモジュールがあれば、反映の前に拒否します。

### xlwrightのVBAのモジュール

- xlwrightが主ブックに置くVBAの関数は、`src/modules/XlWright.bas`（モジュールの名前は`XlWright`）にまとめます。戻り値を型の名前に変える関数（上の「実行ごとに作るモジュール」）と、ダイアログへの事前の応答の関数（段階4、[API](api.md#ダイアログへの事前の応答)）が入ります。
- 全置換の反映で消えないよう、アプリのソースに置きます。要件の利用の前提のとおり、出来上がった主ブックにも残ります。
- このファイルは、xlwrightが書きます。反映の前に（`vba_sync`・`macro_run`・`test_run`のどれでも）、ファイルが無いか、先頭の版の行がxlwrightの版より新しくなく中身が違えば、プラグインに同梱した内容で書き換えます。同じ版のまま中身が変わる開発中の版でも、古い中身を残さないためです。AIエージェントは編集しません。
- アプリのソースに、ほかに`XlWright`という名前のモジュールがあれば、反映の前に拒否します。

## VBAの反映

- 標準・クラスモジュールは、反映のたびにすべて置き換えます。ユーザーがこれまでの開発で使ってきた方式で、差分の判定やモジュールの一時的な改名が要らないためです。シートとブックのモジュールは、削除せずにコードを書き換えます。UserFormには触れません。
- ブックの中にしか無いモジュールは、次の反映で消えます。既存のブックからは、先にソースを取り出してから使います。モジュールを消すための操作は設けず、ソースのファイルを消せば次の反映で消えます。
- シートとブックのモジュールの反映は、段階3で作りました。段階2までは、`src/workbook/`にファイルがあれば、反映の前に`INVALID_REQUEST`で拒否していました。黙って飛ばすと、AIエージェントが反映できたと読むためです。
- 反映では、`src/workbook/`のどのファイルのCodeNameも主ブックにあることを確かめてから、標準・クラスモジュールを置き換え、その後にシートとブックのモジュールのコードを書きます。無いCodeNameがあれば、ブックを変える前に止まります。
- ソースはUTF-8で読み、システムのANSIコードページへ変換し、改行をCRLFにします。変換できない文字があれば、ブックに触れる前に、ファイルと行を返して拒否します。
- `.bas`と`.cls`に`Attribute VB_Name`が無ければ、ファイル名から補います。ファイル名と食い違えば拒否します。
- `src/classes/`のファイルにクラスのヘッダー（`VERSION 1.0 CLASS`の行から`END`まで）が無ければ、標準のヘッダーを補います。
- `src/workbook/`のファイルからは、ヘッダーと`Attribute`の行を除き、コードだけを書きます。
- 途中で失敗したら保存せず、どこまで進んだかを返します。次の反映が全置換でやり直します。
- VBIDEは、PIAを加えずに遅延バインドで扱います。
- 確認済み（段階1、[記録](notes/vba-run.md)）: 標準・クラスモジュールを、遅延バインドの`VBComponents.Import`で取り込めた。`VBAWarnings`が2のままで取り込めた。Importは、ファイルをシステムのANSIコードページ（CP932）として読んだ。UTF-8のファイルの日本語は化けた。そのため、上のANSIへの変換を行います。
- 確認済み（段階1、[記録](notes/vba-run.md)）: 外部のCOMから、標準・クラスモジュールを全削除して全取り込みできた。`Remove`はすぐに効き、名前に番号は付かなかった。`VB_PredeclaredId`・`VB_UserMemId`・`VB_Description`の属性は保たれた。
- 確認済み（段階1、[記録](notes/vba-sync.md)）: ヘッダーの無い`.cls`は、標準モジュールとして取り込まれた。`VERSION 1.0 CLASS`から`END`までの4行を補うと、クラスモジュールになった。
- 確認済み（段階1、[記録](notes/vba-sync.md)）: 名前が既にある時（シートのモジュールの`Sheet1`など）と、32文字の名前は、例外にならず、番号の付いた別の名前で取り込まれた。そのため、取り込んだ後に名前と種類を照合し、食い違えばそのモジュールを消して`SYNC_FAILED`を返します。
- 反映のために変換したファイルは、`<アプリ>/.xlwright/sync/<id>/`に書き、取り込んだ後に消します。
- 確認済み（段階1、[記録](notes/workbook-save-open.md)）: `AccessVBOM`が0の時、`Workbook.VBProject`の取得は`0x800A03EC`で失敗した。この値はExcelの一般的な失敗の値のため、値ではなく、`VBProject`の取得が失敗したことを、`AccessVBOM`が無効として拒否する`detail`に対応付けます。
- 既存のブックから取り出す時は、アプリのフォルダへ写したブック（`.xlwright/extract/<id>/<id>.xlsm`）を`AutomationSecurity=ForceDisable`で開きます。名前を変えて写すのは、主ブックと同じ名前のブックを同時に開けないためです。手順は[API](api.md#vba_extract)にあります。開く前に、ブックのパッケージに`xl/macrosheets/`があれば拒否します。`ForceDisable`がExcel 4.0のマクロを止めるかを、確かめていないためです。
- 確認済み（段階4、[記録](notes/vba-extract.md)）: `ForceDisable`で開いたブックでは、`EnableEvents`が真でも、開く時・再計算・セルの書込みでイベントとUDFが動かず、`Application.Run`は失敗した。開いた後に`AutomationSecurity`を`Low`に戻しても、そのブックのマクロは無効のままだった。`VBProject`に触れられ、標準・クラス・シート・ブックのモジュールのコードを`CodeModule.Lines`で、参照設定を`References`で読めた。再計算でUDFのセルは`#NAME?`になるため、写しは保存せずに閉じます。
- 確認済み（段階4、[記録](notes/vba-extract.md#excel-40のマクロシートの見分け方)）: Excel 4.0のマクロシートを持つ`.xlsm`のパッケージには`xl/macrosheets/`があり、VBAだけのブックには無かった。
- 確認済み（段階3、[記録](notes/test-copy.md#シートとブックのモジュールの書き換え)）: シートとブックのモジュールを`VBComponents.Item(<CodeName>)`で見つけ、`DeleteLines`と`AddFromString`でコードを書き換えられた。保存して開き直した後も残り、イベントが動いた。シート名を変えても`CodeName`は変わらなかった（[Microsoftの説明](https://learn.microsoft.com/en-us/office/vba/api/excel.worksheet.codename)）。無い名前の`Item`は例外になった。
- `Workbooks.Add`で作ったばかりのブックでは、`VBProject`に触れる前の`Worksheet.CodeName`は空でした。そのため、CodeNameは`Worksheet.CodeName`でなく、`VBComponents`の名前で照合します。

## テスト

- テストは、`tests/`の`.bas`にある、引数なしの`Public Sub`で、名前が`Test`で始まるものです。xlwrightは、ソースのファイルからテストを見つけます。
- アサーションのモジュール`XlWrightAssert`は、xlwrightがプラグインに同梱し、写しにだけ取り込みます。アプリのフォルダには置きません。アサーションとテストの結果の形は、[API](api.md#test_run)にあります（人が承認、2026-11-04）。
- テストは、`macro_run`の[実行ごとに作るモジュール](#実行ごとに作るモジュール)と同じく、名前で直接呼ぶ関数から呼びます。アサーションの失敗は`Err.Source`が`XlWrightAssert`のエラーとして上がり、その関数の`On Error`で捕まえて、ほかの実行時エラーと分けます。
- 流れは次のとおりです（段階3で作りました）。テストの中でマクロが行った変更を、主ブックに残さないためです（目標の2）。
  1. `src/`を主ブックへ反映し、保存して閉じます。
  2. `.xlwright/test/<run-id>/`へ、アプリのフォルダを写します。写すのは、`src/`・`tests/`と、`.`で始まるフォルダ（`.xlwright/`・`.git/`など）を除くすべてです。主ブックも同じ名前で写ります。
  3. 写しの主ブックを開き、`tests/`とアサーションのモジュールを取り込みます。段階4で、取り込んだ後に`vba_check`と同じコンパイルを加えます。エラーの時は、テストを実行せずに5へ進みます（人の判断、2026-11-05、[API](api.md#test_runの前のコンパイル)）。まだ無い関数を呼ぶテストで、専用のExcelを終えずに返すためです。
  4. テストを1つずつ実行し、結果を集めます。
  5. 写しを保存せずに閉じ、`<run-id>/`を消します。主ブックを開き直します。
- 2でアプリのフォルダごと写すのは、主ブックからの相対の参照（`ThisWorkbook.Path`からの`data/`など）を、写しでも成り立たせるためです。テストがデータのファイルを書き換えても、その変更は写しに留まります。
- 5で主ブックを開き直せない時（人が日常のExcelで開いた時など）は、開いたブックの`ReadOnly`が真の時も含め、専用のExcelを[終了](#終了)の2〜5で終え、セッションを閉じて`CONFLICT`で知らせます。テストの結果は`data`に入れて返します。
- 1で主ブックを保存するため、`test_run`の後に`session_end`で保存しないと指定しても、`test_run`の前の変更は残ります。このことは`test_run`の説明に書きます。代わりの形の`SaveCopyAs`では、主ブックを保存しません。
- 確認済み（段階3、[記録](notes/test-copy.md#テストの写しの流れ)）: この流れは成立した。写しを`EnableEvents=False`で開くと`Workbook_Open`は動かず、外部のCOMの`Workbooks.Open`では`Auto_Open`も動かなかった。主ブックを閉じた後は、主ブックの名前で修飾した`Application.Run`が写しのマクロを呼び、`ThisWorkbook`も`Workbooks("<主ブックの名前>")`も写しを指した。同じ名前のブックは同時に開けないためです。テストが主ブックのフォルダを絶対パスで書き換えることは防げません。
- 確認済み（段階3、実Excelの結合テスト`RunsTheTestsInACopyAndLeavesTheAppAsItWas`）: `test_run`の1回で、通るテスト、アサーションの失敗、実行時エラーを受け取れた。テストが書き換えたセルと`data/`のファイルは、主ブックとアプリのフォルダに残らず、写しのフォルダは消え、セッションが続いた。
- 実行の上限は、テストを実行している間に確かめます。保存・写しを開く・開き直すには、それぞれの期限（[期限の表](#期限と大きさの上限)）を使います。
- 確認済み（段階3、[記録](notes/test-copy.md#外部のcomからのコンパイル)）: `VBE.CommandBars.FindControl(1, 578)`（「VBAProject のコンパイル」）の`Execute`で、`ActiveVBProject`のプロジェクトをコンパイルできた。正しいコードではダイアログが出ず、コントロールの`Enabled`が偽になった。
- 不一致（段階3、[記録](notes/test-copy.md#非表示のexcelでコンパイルのエラーがダイアログで止まらないか)）: 非表示のExcelでも、コンパイルのエラーではダイアログとVBEのウィンドウが人の画面に表示された。`Execute`はすぐに戻り、ダイアログを開いたままでも以後のCOMの呼出しは通った。ダイアログの本文はエラーの説明で、`ActiveCodePane.GetSelection`がエラーの行を指すことがあった。ダイアログを`WM_CLOSE`で閉じるとQuitで終わり、開いたままだと終わらなかった。
- そのため、`vba_check`は、コンパイルの後にダイアログを見張り、見つけたら文字と選択の位置を読み、`WM_CLOSE`で閉じ、VBEのウィンドウを隠します（人が承認、2026-11-04、[API](api.md#vba_check)）。ダイアログは人の画面に短い間表示されます。閉じたダイアログが残る時は、Quitで終わらないことがあるため、専用のExcelを終えます。
- ダイアログは、マクロの実行中と同じ[規則](#失敗の返し方と記録)で見つけます。コンパイルのエラーのダイアログの間も、`XLMAIN`の1つが無効でした（[記録](notes/test-copy.md#非表示のexcelでコンパイルのエラーがダイアログで止まらないか)）。コントロールが初めから無効の時は、コンパイル済みとして`Execute`しません。無効のコントロールの`Execute`は失敗したためです。
- 確認済み（段階3、実Excelの結合テスト`ChecksTheCompileAndReportsACompileErrorWithItsLine`）: 宣言の無い変数で`compiled`が偽と、モジュールと行が返り、その後もセッションが続いた。単独で4回と全体の中で1回通り、専用のExcelは残らなかった。

## 起動時の設定

- 専用のExcelは`Visible=False`で起動します。非表示を、終了してよい根拠には使いません。
- 所有を確定した直後に、`UserControl`を真にします。Microsoftの説明は、`UserControl`が偽の時、セッションの最後のオブジェクトを解放するとExcelが終わるとしています（[Microsoftの説明](https://learn.microsoft.com/en-us/office/vba/api/excel.application.usercontrol)）。終わると、触らずに残すはずのExcelが、ほかのブックの保存していない変更とともに消えます。
- 確認済み（段階1、[記録](notes/sta-com.md)）: `UserControl`が偽のまま参照をすべて解放すると、非表示の専用のExcelは約2.5秒で自ら終わった。真にしてから解放すると30秒経っても終わらず、真にしてからQuitを呼ぶと終わった。
- 主ブックとテストの写しは`AutomationSecurity=Low`で開きます。開発中のコードとして信頼します。
- xlwright自身のOpen・Close・編集の間は`EnableEvents=False`にし、終わったら元に戻します。マクロとテストの実行中は変えません。イベントの抑止を、VBA全体の実行の防止には使いません。
- `DisplayAlerts=False`は、保存しないClose、シートの削除のような明示の操作の間だけにします。
- 計算の方法は変えません。値を読む前に、`Calculate`と`CalculationState=xlDone`の確認を、値の取得と同じ操作の中で行います。
- 確認済み（段階1、[記録](notes/workbook-save-open.md)）: `Calculate`の後の`CalculationState`は`xlDone`で、計算を終えた値を読めた。`AutomationSecurity=Low`と`EnableEvents=False`で、VBAの無いブックを開けた。
- 確認済み（段階1、[記録](notes/vba-run.md)）: `AutomationSecurity=Low`で開いた主ブックのマクロを、`VBAWarnings`が2のまま`Application.Run`で実行できた。`EnableEvents=False`の間に開くと、`Workbook_Open`は動かなかった。

## 日常のExcelとの分離

- COMで接続するのは、自分が起動した専用のExcelと、同一性を照合した残りの専用のExcelだけです（目標の4）。
- ROTの`GetActiveObject`は使いません。ROTに登録されたExcelのどれかを返すため、日常のExcelに接続するおそれがあります。
- 専用のExcelは非表示のまま使い、DDEに関わる設定は変えません。
- 人が開いたブックが専用のExcelに入ってしまった時、そのブックがアプリのフォルダの外にあれば、[終了](#終了)と[片付け](#残った専用のexcelの片付け)のブックの照合が検出して止まります。アプリのフォルダの中のブックは、照合では見分けられません。
- 確認済み（段階2、[記録](notes/human-open-and-show.md)）: 非表示の残った専用のExcelがある時に、人がエクスプローラーから開いたブックは、`/automation`を含まない新しいExcelで開き、専用のExcelには入らなかった。
- 確認済み（段階2、[記録](notes/stage2-scenarios.md)）: 日常のExcelと残った専用のExcelが動いている時に、人がエクスプローラーから開いた主ブックは、日常のExcelに入り、専用のExcelには入らなかった（1回）。そのため、入らない方式は調べません。

## 人への引継ぎ

xlwrightが止まって知らせる時に、人が取る手順です。段階2で揃えます。

- 止まる時の応答には、理由、記録したPIDと生成時刻、所有記録のパス、人が取る手順を含めます。
- 起動前の印だけが残って止まる時は、記録したPIDがありません。代わりに、印の時刻と、数えたEXCELのPIDと生成時刻を含めます。数えたEXCELには、ほかの会話の専用のExcelや日常のExcelが入りえます。そのため、終了は勧めません。人が各プロセスの持ち主を確かめ、ほかの会話のものなら、その会話が終わってから開始し直します。
- 形式が不正な記録で止まる時は、人が記録を読み、記録したExcelが残っていないことを確かめてから、ファイルを消す手順を含めます。
- 保留中のCOM呼出しが残って止まった時は、会話を閉じてから表示要求のコマンドを使う手順を含めます。会話を閉じるまで、サーバーが排他を持つためです。
- 空の所有記録で止まる時は、人がファイルを消してから開始し直す手順を含めます。空のファイルは、専用のExcelを起動する前にだけ残るためです（[所有記録の形式](#所有記録の形式)）。
- 非表示のExcelは、表示要求のコマンドで人へ見せます（[API](api.md#表示要求のコマンド段階2人が承認2026-11-04)）。サーバーの実行ファイルのサブコマンドにし、プラグインに入口のスクリプトを同梱します（人の判断、2026-11-04）。排他・所有記録の読み・プロセスの照合を、開始と同じ部品で行うためです。
- コマンドは、アプリの排他を取ります。会話ごとにサーバーが動く構成で、ほかのアプリの会話を止めずに済むためです。所有記録が無い時は、ファイルを作りません。
- コマンドは、人が確かめ終えたと入力するまで、排他を持ち続けます。人が確かめている間に、別の会話の開始がそのExcelを片付けないためです。その間の開始は、使用中として止まります。
- 人は、表示したExcelを確かめて閉じ、コマンドへ確かめ終えたと入力します。プロセスが残り、ブックのウィンドウが無ければ、コマンドが同一性と`/automation`を照合してから終了させます（人の判断、2026-11-04）。人が閉じた後もプロセスが残ったためです（[記録](notes/human-open-and-show.md)）。次の開始が、所有記録を完了にします。
- 確認済み（段階2、[記録](notes/human-open-and-show.md#表示要求のコマンド)）: 会話を閉じて残した専用のExcelを、人が入口のスクリプトから見て閉じ、`done`の後にコマンドが終了させて0で終わった。次の開始が、所有記録を完了にした。
- 確認済み（段階2、[記録](notes/human-open-and-show.md)）: 非表示の残ったExcelは、COMを使わずに、`EXCEL7`を持つ`XLMAIN`への`ShowWindow`で人へ見せられた。人が閉じた後も、プロセスは90秒の間に終わらず、`EXCEL7`の無い形で残った（1回）。そのため、残ったプロセスは、上のとおりコマンドが照合して終了させます。

## 失敗の返し方と記録

- 失敗の返し方と共通のエラーコードは、[API](api.md#共通の規約)にあります。
- 診断の記録は`<アプリ>/.xlwright/logs/<session-id>.jsonl`に置きます。失敗の応答から、記録のパスを辿れるようにします。
- 実行時間の上限を過ぎた時は、専用のExcelのウィンドウの状態を記録します。`XLMAIN`の有効状態と、ダイアログの有無です。
- 専用のExcelのプロセスの`XLMAIN`のどれかが無効で、同じプロセスに表示されて有効な`XLMAIN`以外のウィンドウがある時に、そのウィンドウをダイアログとします。クラス名の`#32770`には頼りません。
- ExcelMcpの`ExcelDialogProbe.cs`は、ウィンドウの所有者を辿って`XLMAIN`に届くかで見分けます。この形は採りません。マクロが出したダイアログには所有者が無いか、所有者がVBEのウィンドウだったためです（[記録](notes/dialog-probe.md)）。
- 読んだダイアログの文字は、応答に返し、診断の記録には書きません。MsgBoxの本文にはセルの値が入りうるため、要件の「セル値やVBA全文を無条件にログへ出しません」に従います。文字数は、[応答の大きさの上限](api.md#成功と失敗)に従います。
- 文字は、短い時間で区切って読みます（ExcelMcpは合計500ミリ秒）。読み終えなくても、上限で終了させます。
- 確認済み（段階1、[記録](notes/dialog-probe.md)）: マクロの実行中の実行時エラー・コンパイルエラー・MsgBoxのダイアログを、250 msごとの見張りで最初の見張りのうちに見つけ、題名と本文を`WM_GETTEXT`で読めた。終わらないマクロ（ダイアログ無し）を、ダイアログと見誤らなかった。
- ダイアログを見つけられない時も、上限で終了させる規則は変えません。

### 診断の記録の形式（人が承認、2026-11-04）

人が後から、どのセッションで、どの操作が、どう終わったかを追うための記録です（要件の仕組みの「人が後から原因を追える記録」）。ExcelMcpは、環境変数で有効にした時だけ標準エラーへ書き、ファイルの記録は持ちません。xlwrightは、会話が閉じた後にも人が読めるよう、ファイルに残します。

- `session_start`が呼ばれ、アプリのフォルダが[パスの制限](#パスの制限)と主ブックの規約を通った時に、新しい記録のファイルを1つ作ります。`<session-id>`は、作った時刻のUTCと乱数の`20261104T025606Z-1a2b3c4d`の形です。開始が失敗した時も、ファイルは残ります。
- 1行に1つ、UTF-8（BOM無し）のJSONを追記し、行ごとに`Flush`します。各行は`time_utc`（ラウンドトリップ形式）と`event`を持ちます。
- 書く出来事と項目:

| `event` | 項目 |
| --- | --- |
| `start` | `app`、`build_id`、`server_pid` |
| `cleanup` | 残ったExcelの`pid`・`started_at_utc`、`ended_by`か、触らずに止まった時の`detail` |
| `owned` | 所有を確定したExcelの`pid`・`started_at_utc` |
| `call` | `tool`、`elapsed_ms`、成功なら`ok`が真、失敗なら`code`と`detail` |
| `windows` | 期限切れ・ダイアログで終了させる前の、`XLMAIN`ごとの有効状態の配列（`xlmain_enabled`）と、ダイアログの有無（`dialog`） |
| `end` | `ended_by`（`quit`・`terminate`）、`exit_confirmed` |

- 書かないもの: 引数と戻り値の値（セルの値・数式・マクロの引数と戻り値）、VBAのソース、ダイアログの文字、失敗の`message`、Excelが返した例外の文。どれも、セルの値やソースが入りうるためです。`call`の`tool`と、`macro_run`の時の`macro`（`<モジュール>.<プロシージャ>`の名前）だけを書きます。
- セッションの間の失敗の応答には、`data.log`に記録のパスを入れます。リポジトリからの相対パスで、区切りは`/`です。記録を書けなかった時は、`data.log`を省きます。
- 記録の書込みの失敗では、ツールを失敗にしません。原因を追う助けで、操作の結果を変えないためです。
- 記録のファイルは消しません。数が問題になったら、消す規則を人と決めます。
- 診断の記録はGitの管理から外します（`.xlwright/`の全体）。

## サーバーとビルドとプラグイン

- サーバーの引数は`--project <リポジトリ>`と`--no-excel`です。`--project`の渡し方は[パスの制限](#パスの制限)にあります。`--project`は必須で、1回だけ、在るフォルダを渡します。外れた時は、使い方を標準エラーに書いて終了コード2で終わります。
- `--no-excel`は、Excelを起動しないモードです。Inspectorと通常の確認で使います。`session_start`は検証の後に、`INVALID_REQUEST`・`detail: NOT_IMPLEMENTED`で止まり、所有記録に触れません。
- 製品のツール`server_info`が、版とビルドの識別子を返します。開発用だけのツールは作りません。
- ビルドは毎回、変わらない置き場`.xlwright/builds/<build-id>/`へ出します。開発版のプラグイン、Inspector、実Excelのテストは、すべてこの置き場から起動します。動いているサーバーがDLLを掴んでいても、次のビルドを妨げないためです。
- 確認の入口は1つのコマンドにし、AIエージェントが人なしで回します。工程は、依存の復元、ビルドと置き場への出力、Excelを起動しないテスト、Inspectorでの`tools/list`と`server_info`（今回のビルドを`--no-excel`で起動）、Markdownのチェック、`git diff --check`、通ったビルドの`.xlwright/builds/latest.json`への記録、の順です。
- 古いビルドは、新しい5つと、`latest.json`が指すビルドを残して、フォルダの単位で消します。消す前にフォルダの名前の変更を試し、失敗したもの（動いているサーバーが使っている見込み）は飛ばします。
- 確認済み（段階0、[記録](notes/build-folder-rename.md)）: 開いた会話が使っているビルドのフォルダは、名前の変更が`IOException`で失敗した。
- 開発版のプラグインは`xlwright-dev`、利用する版のプラグインは`xlwright`という名前にします。どちらも、プラグインの中のMCPサーバーの名前は`xlwright`です。
- Claude Codeはツールに`mcp__plugin_<プラグイン名>_<サーバー名>__`を付けます（[MCP](https://code.claude.com/docs/en/mcp.md)）。そのため、ツールの名前は`mcp__plugin_xlwright-dev_xlwright__<ツール名>`と`mcp__plugin_xlwright_xlwright__<ツール名>`に分かれます。事前の許可の設定は、この名前で書きます。
- 開発版の入れ方: `plugins/xlwright-dev/`を、`--plugin-dir`と同じ形で読み込ませます。プラグインはその場所のまま読み込まれ、`${CLAUDE_PLUGIN_ROOT}`はこのフォルダを指します（[プラグインの読み込み](https://code.claude.com/docs/en/plugins/loading.md)）。プラグインの`plugin.json`には`version`を書きません。確認の入口が通ると、`plugins/xlwright-dev/.mcp.json`（Git管理外）を書き出します。中身は、`dotnet`で`${CLAUDE_PLUGIN_ROOT}/../../.xlwright/builds/<build-id>/XlWright.McpServer.dll`を起動し、`--project`にこのリポジトリの完全なパスを渡すものです。
- 人は、デスクトップアプリのCodeのこのリポジトリのプロジェクトの環境の`.env`に、`CLAUDE_CODE_PLUGIN_DIRS`として`plugins/xlwright-dev`の絶対パスか`~`で始まるパスを書きます。アプリの設定のため、人が行います。デスクトップアプリの画面ではローカルのフォルダのマーケットプレイスを追加できず、プロジェクトの設定ファイルの`env`では、アプリを再起動しても読み込まれませんでした（[記録](notes/dev-plugin-loading.md)）。
- 確認済み（段階0と段階1、[記録](notes/dev-plugin-loading.md)）: プロジェクトの環境の`.env`の形では、このリポジトリの新しい会話にだけ開発版のサーバーが起動し、ほかのプロジェクトの会話には起動しなかった。ユーザーの設定の`env`に書く形でも読み込まれたが、すべてのプロジェクトの会話でサーバーが起動した。
- 開発版は、`--project`に`${CLAUDE_PROJECT_DIR}`ではなくこのリポジトリを渡します。ほかのプロジェクトの会話で読み込まれた時も、ほかのプロジェクトのアプリでの開始を[パスの制限](#パスの制限)で拒否させるためです。サーバーが起動しても、Excelは`session_start`まで起動しません。
- 確認済み（段階0、[記録](notes/dev-plugin-loading.md)）: 新しい会話は、確認の入口が最後に通したビルドを読み、開いたままの会話は前のビルドを使い続けた。
- 利用する版は、.NETの実行環境を同梱する自己完結の形で発行し、プラグインに入れます。別の端末で.NETを入れる手順を省くためです（[提供形態](requirements.md#利用環境と提供形態)）。
- 未確認（段階4）: 会社のPCの管理設定が、プラグインの入手元を制限していないか。GitHubから配布物を取得できるか。成立しない時は、リポジトリを手元に写し、ローカルのフォルダのマーケットプレイスとして追加します。
- AIエージェントへの手順（報告の前にセッションを終えること、マクロにアプリのフォルダの外を変更させないこと、フォルダの規約）は、プラグインのスキルで渡します。プラグインはスキルを同梱できます（[プラグインのマニフェスト](https://code.claude.com/docs/en/plugins-reference.md)）。
- 段階2で、開発版のプラグインに`skills/xlwright/SKILL.md`を作りました（中身は人が承認、2026-11-04）。中身は、上の3つと、APIがAIエージェントへ求める扱い（失敗の`message`に従うこと、`STATE_UNKNOWN`で開始し直す条件、`cleanup`の報告）です。利用する版のプラグインへの同梱は、段階4で決めます。
- 確認済み（段階2）: 新しい会話の使えるスキルの一覧に、`xlwright-dev:xlwright`として出た。

## 本体の部品の境界

- `XlWright.Core`は、MCPに依存しません。Excelの操作を専用のSTAの中に閉じます。
- Excelに触れる部分は、Coreの中で差し替えられる境界の向こうに置きます。Excelなしで、Coreの残りをテスト駆動で作るためです。
- Coreは、ExcelとVBIDEを、PIAを使わずに遅延バインド（`dynamic`）で扱います（人が判断）。新しい依存が要らず、PIAの型を埋め込んだ配布物の利用条件を確かめずに済み、段階1の実験で必要な操作が通ったためです（[記録](notes/vba-run.md)）。NuGetの`Microsoft.Office.Interop.Excel`は、[パッケージのページ](https://www.nuget.org/packages/Microsoft.Office.Interop.Excel/)が再梱包のためライセンスが無く、サポート対象外と明記しているため、使いません。
- 遅延バインドでは、呼出しの型を検査できません。Excelに触れる部分をCoreの狭い境界の中に閉じ、実Excelの結合テストで確かめます。
- `XlWright.McpServer`は、stdioのMCPサーバーです。ツールの引数を確かめ、Coreを呼び、結果を返します。
- テストは、Excelを起動しないものと、実Excelを起動するものを分けます。
- Excelを起動しないテストは、AIエージェントが確認の入口で毎回実行します。
- 実Excelを起動するテストは、別の入口から実行します。日常のExcelと同じ端末で動くためです（目標の4）。
- 確認済み（段階0、[記録](notes/excel-start-stop.md)）: AIエージェントのシェルから、実Excelを起動して終了できた。
- 置き場は次のとおりです。
  - `src/XlWright.Core/`
  - `src/XlWright.McpServer/`
  - `tests/XlWright.McpServer.Tests/`: Excelを起動しないテスト。Coreの単体のテストと、サーバーを実プロセスで起動するテスト。
  - `tests/XlWright.RealExcel.Tests/`: 実Excelを起動するテスト。
  - `spikes/`: 分からない振る舞いを確かめる、捨てる前提の実験。
  - `plugins/xlwright-dev/`: 開発版のプラグイン。
