# 0013: ツールを読むツールと変えるツールに分ける

- Status: Accepted

2026-11-02にユーザーが承認しました。
状態を変える操作、長く走る操作、頻繁に使う操作は、単独のツールにします。
それ以外は、対象ごとに読むツール`<対象>_get`と変えるツール`<対象>_edit`の2つにし、変える操作は引数`action`で選びます。
複数の操作をまとめて送るツールは作りません。一覧は[API](../api.md#ツールの一覧)にあります。

## 背景

- 範囲の表の操作は、およそ70あります。
- Claude Codeは既定で、MCPのツールの定義を後から読み込みます。最初に読むのは、ツールの名前とサーバーの説明だけです（[MCP](https://code.claude.com/docs/en/mcp.md)）。
- 注釈（読み取りだけ・破壊的）は、ツールごとに付きます。
- 要件の目標の1により、ツールはすべて事前に許可します。許可の単位としての粒度は、判断に効きません。

## 検討した代替案

- 操作ごとに1つのツールにする案（約70個）は、引数のスキーマが最も単純です。一方で、初めて使う前にモデルが定義を探す回数が増えます。
- 対象ごとに1つのツールにする案（約15個）は、ツールが最も少なくなります。一方で、読み取りと削除が1つのツールに混ざり、全体を破壊的として注釈するしかありません。
- 複数の操作をまとめて送るツールは、往復の回数を減らせます。一方で、途中で失敗した時に、どこまで変わったかの報告が複雑になります。

## 影響

- 読むツールには、読み取りだけの注釈を正しく付けられます。
- 名前が`<対象>_get`・`<対象>_edit`の形にそろうため、モデルが名前を予測できます。
- 既にある対象に操作を加える時は、変えるツールの`action`を加えます。ツールの数は増えません。新しい対象を加える時は、2つのツールが増えます。
