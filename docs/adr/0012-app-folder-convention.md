# 0012: アプリのフォルダを規約で構成する

- Status: Accepted
- Supersedes: 0006

2026-11-02にユーザーが承認しました。
アプリのフォルダは規約で構成し、設定ファイルを持ちません。
直下のブック1つが主ブック、`src/modules`・`src/classes`・`src/workbook`がVBAソース、`tests/`がテストのモジュールです。
開始ではアプリのフォルダだけを渡します。テストのモジュールは、テストの写しにだけ取り込みます。
規約の詳細は[設計](../architecture.md#アプリのフォルダ)にあります。

## 検討した代替案

- アプリごとの設定ファイル（`xlwright.json`）で、主ブックとVBAソースのフォルダを指す案を比べました。既存のアプリを移さずに使えます。一方で、キーと検証を保守し続ける必要があります。`.xlsx`から`.xlsm`へ変えた時に、設定も書き換える必要があります。
- 開始の引数で主ブックを渡す案は、会話ごとに主ブックの名前を渡す必要があり、規約の案より手順が増えます。
- VBAソースを1つのフォルダに平置きし、`.cls`の名前がシートのCodeNameと同じならシートのモジュールとみなす案も比べました。シートを消した後に残ったソースが、黙ってクラスモジュールとして取り込まれます。
- シートとブックのモジュールだけをフォルダに分ける案も比べました。ユーザーは、拡張子とフォルダの両方で種類を表す形を選びました。xlflowの`src/modules`・`src/classes`・`src/workbook`の分け方を参考にしています。
- テストのモジュールを`src/`に置き、主ブックにも取り込む案（前の設計の`'@TestModule`）を比べました。出来上がった主ブックにテストが残ります。

## 影響

- 既存のアプリは、使い始める時に1回だけこの形へ移します。
- 直下にブックが無い時は、主ブックを作るためだけのセッションを始めます。新しいアプリも、同じ開始の手順で作れます。
- 主ブック以外のブックは、アプリのフォルダの直下に置けません。サブフォルダに置きます。
- 拡張子とフォルダが食い違うファイルは、反映の前に拒否します。
- 0006の`project.json`は使いません。厳密なJSONで解析する方針は、所有記録の形式に引き継ぎます。
