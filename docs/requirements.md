# 要件

## 背景

AIエージェントを使ったExcel VBAアプリケーションの開発を、数か月にわたって実践してきました。
1つのリポジトリで、複数のアプリケーションを開発・管理することもありました。
ソースを修正するたびに、次の流れを繰り返していました。

1. AIエージェントがVBAソースとテスト用のデータ（ブックやCSV）を作ります。
2. 人が取り込み用のマクロで、ソースをブックへ取り込みます。
3. 人がマクロを実行し、結果を保存します。
4. AIエージェントが結果のシートをチェックします。

2と3は人の操作で、反復のたびに手間がかかっていました。

シート構成・書式・テーブルも、ある程度はAIエージェントに作らせていました。
Excelを起動せずにファイルを直接編集する方式で、ファイルの破損や作成漏れが起きました。
参照用のブックからシート単位でコピーせず、セルを1つずつ写すこともありました。
VBA以外も、実際のExcelで編集できるようにしたいと考えています。

当面の利用者は開発者本人だけです。
会社支給のPCを使い、別の端末や仮想マシンを用意できません。
そのため、日常業務のExcelと開発用のExcelが、同じ端末・同じユーザーで動きます。

## 目的

xlwrightの目的は、Excelアプリケーションの開発をAIエージェントに任せ、作成・テスト・修正のループを自走で回させて、効率化することです。

人が担当するのは、作業の依頼、仕様の決定と重要な設計変更、結果の確認と承認です。
依頼から報告までの間、AIエージェントは人の操作なしで作成・テスト・修正を続けます。
途中で仕様の決定や重要な設計変更が必要になった時は、止まって人に確認します。

## 目標

以下では、次の呼び方を使います。

- アプリ: 開発するExcelアプリケーション。1つのアプリが、リポジトリの中に1つのフォルダを持ちます。
- 主ブック: アプリの開発の対象のブック。
- 会話: Claude Codeの会話。
- セッション: アプリのフォルダを指定してxlwrightで開始してから、終了するまで。
- 日常のExcel: 人が起動したExcel。
- 専用のExcel: xlwrightが起動したExcel。

次の1〜3を満たし、その間4・5を守れたら、目的を達成したとみなします。

1. 依頼から報告までの間、人の操作なしで作成・テスト・修正のループが回る。
   人の操作として数えるのは、ループを進めるためのExcelとファイルの操作、ツールの許可、続行の指示です。
   依頼の前の設定、AIエージェントの質問への回答、4・5で止まった時と、3で片付けてよいと確かめられずに止まった時の対応は数えません。
   xlwrightが原因で人の操作が要った場合だけを、不合格とします。
2. 出来上がった主ブックが正しい。主ブックをExcelで修復なしに開け、判定の前に用意した確かめる項目を満たし、テストが通る。
3. 専用のExcelを片付ける。
   - 報告の時点で専用のExcelは残らず、人は主ブックをExcelで開いて確認できる。
   - 異常時も、AIエージェントが片付ける。作業の途中で会話を閉じた場合は、遅くとも次にその主ブックでセッションを開始する時に片付ける。それまでの間も、人は主ブックを読み取り専用で開いて確認できる。
   - 残った専用のExcelを片付ける対象は、どの会話も使っておらず、アプリのフォルダの中のブックだけを開いていると確かめられるものに限る。確かめられない時は触らず、止まって人に知らせる。保存していない変更は捨ててよい。
   - 実行時間の上限を過ぎた時は、今の会話が使っている専用のExcelを、応答しなくても終了してよい。
4. 日常のExcelに影響しない。
   - xlwrightは日常のExcelに接続しない。
   - 主ブックを日常のExcelが編集できる状態で開いている時は、閉じるよう知らせて止まる。
   - 開発中も、人は主ブック以外のブックを日常のExcelで開き、編集・保存できる。
5. 同じ主ブックのセッションを別の会話が使用中の時は、使用中と知らせて止まる。使用中の会話は、そのまま作業を続けられる。

### 確かめ方

判定用の題材（練習用の小さな業務アプリ）を、2回の依頼で作ります。
題材は、範囲の表の各行から、操作を1つ以上使います。題材の内容と確かめる項目は判定の前に用意し、人が承認します。
会話Aで作成を依頼し、会話Bで仕様の変更を依頼します。
仕様の変更は、マクロと数式の両方を直す内容にします（例: CSVの列が1つ増える）。
判定は、もう1つのアプリを置いたリポジトリで行います。
判定の後に、そのアプリのファイルが変わっていないことと、報告の後に専用のExcelが残っていないことを確かめます。

4・5と異常時は、次の起こし方で別に確かめます。矢印の後が、期待する結果です。

- 会話Aの作業中に、日常のExcelを起動していない状態で、人がリポジトリの外のブックをエクスプローラーから開き、編集・保存する → ブックは日常のExcelで開き、会話Aは作業を続けられる（4）。
- 主ブックを日常のExcelで編集できる状態で開いたまま、会話Bで開始する → 閉じるよう知らせて止まる（4）。
- 会話Aの作業中に、会話Bで同じ主ブックのセッションを開始する → 会話Bは使用中と知らせて止まり、会話Aは作業を続けられる（5）。
- 会話Aを作業の途中で閉じ、人が主ブックを読み取り専用で開く → 開いて確認できる。その後、会話Bで開始する → 残った専用のExcelを片付けて開始する（3）。
- テストの中で、実行時エラー、コンパイルエラー、終わらないマクロを1回ずつ起こす → AIエージェントが失敗を受け取り、必要なら片付けて、作業を続けられる（3）。
- テストのマクロでアプリのフォルダの外のブックを開いたまま、会話Aを閉じる。その後、会話Bで開始する → 残った専用のExcelに触らず、知らせて止まる（3）。

### 目標から外したもの

- 別々のアプリを、2つ以上の会話で同時に開発すること。拒否はしませんが、確かめません。
- PCの動きの重さ。開発中に重くなるのは許容します。
- ループ1回の所要時間。
- 途中で判断が要る時に、AIエージェントが止まって確認すること。AIエージェントの振る舞いで、再現して確かめにくいためです。
- 回線の不調などで途切れた後の再開。再現して確かめにくいためです。

## 範囲

xlwrightは、Excel COMで行える主要な操作と、AIエージェントがその操作を安全に繰り返すための仕組みを提供します。
xlwrightの機能にするのは、Excelが無いとできない操作か、AIエージェントがほかの手段では安全に行えない操作に限ります。

主要な操作は次の表で示します。設定できるものは、読み取りと解除もできます。
表に無い操作は、範囲に含みません。必要になった時に、人が判断して表へ加えます。加える時に、どの版に入れるかも人が決めます。
表の操作が実機で行えないと分かった時は、人が判断して後続の範囲へ移します。

Ver1.0.0は、表の操作と下の仕組みをすべて備え、[目標](#目標)を満たす最初の版です。作る順はロードマップで決めます。

### 操作

対象は主に操作が働きかけるExcelのオブジェクトで分け、印刷・出力と実行・テストは機能でまとめます。
行・列はセル範囲の一種ですが、操作が多いため別に分けます。

| 対象 | 操作 |
| --- | --- |
| Excel全体 | 計算の方法（自動・手動）の設定、再計算 |
| ブック | 新規作成、保存、`.xlsx`から`.xlsm`への変更、ブックの保護（パスワード付き） |
| シート | 一覧、作成・名前の変更・削除・順序の変更、コピー（同じブックの中、アプリのフォルダにある別のブックから）、表示・非表示（VBAからしか戻せない隠し方を含む）、シートの保護（パスワード付き） |
| ウィンドウ | 表示の設定（目盛線・行番号と列番号・拡大率）、ウィンドウ枠の固定 |
| セル範囲 | 使われている範囲の取得、値・数式の読み書きと消去、計算結果と表示される文字列の取得、書式（表示形式・フォント・塗りつぶし・罫線・配置）、結合、入力規則、条件付き書式、ロック、範囲のコピー（値・数式・書式）、並べ替え、オートフィルター |
| 行・列 | 表示・非表示、挿入・削除、列の幅・行の高さ、幅と高さの自動調整 |
| 名前 | ブック全体とシートの中の名前の作成・削除・一覧と、名前と指す先の変更。指す先は範囲・数式・定数 |
| テーブル | 一覧、作成・削除・名前の変更、範囲の大きさの変更、列の追加・削除、行の追加・削除、計算列、並べ替え、オートフィルター |
| 図形 | シートのボタン（フォームコントロール）の作成・削除・一覧と、マクロの割り当て |
| 印刷・出力 | 印刷の設定（印刷範囲・用紙・向き・余白・ヘッダーとフッター・拡大縮小） |
| VBA | モジュールの一覧、ソースのとおりの反映（ソースに無い標準・クラスモジュールはブックから消える）、シートとブックのモジュールの更新、既存のブックからの取り出し、コンパイルの確認、参照設定 |
| 実行・テスト | マクロの実行と結果の取得、実行中の状態の確認、マクロが出すダイアログ（メッセージ・入力・ファイル選択・フォルダー選択・保存先の指定）への事前に決めた応答（キャンセルを含む）、VBAで書いたテストの実行と結果の取得 |

`.xlsx`から`.xlsm`へ変えた後は、新しい`.xlsm`が主ブックになります。元の`.xlsx`は、AIエージェントがGitの操作で消します。
既存のブックにあるUserFormには触れず、そのまま残します。

### 仕組み

- 開始時に、対象のアプリのフォルダを指定する。主ブックは、フォルダの規約で決まる。xlwrightが開くブックは、アプリのフォルダの中に限る。保存するのは主ブックだけ（目標の3・4）。
- セッションの開始・状態の照会・終了。終了では、主ブックを保存して（または保存せずに）閉じ、専用のExcelを終える（目標の1・3）。
- 使用中の検出。主ブックを読み取り専用でしか開けない時、別の会話が同じ主ブックのセッションを使っている時、日常のExcelが主ブックを編集できる状態で開いている時（目標の4・5）。
- 人が開くブックを、専用のExcelに入れない（目標の4）。
- 残った専用のExcelの片付け（目標の3）。
- テストの中でマクロが行った変更は、主ブックに残らない（目標の2）。
- 実行時間の上限。時間を過ぎたら専用のExcelごと片付け、AIエージェントは専用のExcelを起動し直して作業を続けられる（目標の1・3）。
- 何が失敗したかをAIエージェントへ返し、人が後から原因を追える記録を残す（目標の1）。

### 作らないもの

- ファイルとしてのブックの名前の変更・削除・コピー。AIエージェントが、ブックを閉じてからGitとファイルの操作で行います。
- テスト用のデータ（CSVやブック）の作成と読み込み。CSVはAIエージェントが書き、ブックの作成と読み込みはテストのマクロが行います。
- VBAプロジェクトの保護の設定・解除。Excelの外から行う標準の手段がありません。
- 一般利用者向けのGUI、独立したCLI、公開SDK、リモート接続。利用者は本人だけのためです。
- 独自のバックアップ、自動スナップショット、OOXMLを正本としたブックの組み立て、Git操作の代行。

### 正本

VBAソースはファイルを正本とし、主ブックへ一方向に反映します。
VBAソース以外（シート・数式・書式・参照設定・UserFormなど）は、主ブックを正本とし、Excelで編集します。

## 利用環境と提供形態

- AIエージェントとWindows版Excelは、同じWindows端末・同じユーザーで動かします。
- 初期の検証対象はWindows 11 x64、.NET 10、Microsoft 365 Excel 64-bitのデスクトップ版です。他の環境は未検証です。
- Claude Codeから利用する、ローカルstdioのMCPサーバーを提供します。Codexは当面の対象外です。
- MCPサーバーは、Claude Codeのプラグインとして配布します。導入・登録・更新では、次のことができるようにします。
  - 別の端末でも、同じ手順で導入できる。
  - xlwrightを使うリポジトリを選んで有効にできる。
  - 使用中の会話を止めずに更新できる。新しい版は、次に始めた会話から使われる。
  - 開発中のxlwrightと、利用する版を分けて使える。
- 日常のExcelと専用のExcelが同時に動く前提です。

これらは設計上の対象です。現在の実装・検証状況は [README](../README.md#現在の状態) を参照してください。

## 利用の前提

- Excelのトラストセンターで「VBAプロジェクト オブジェクト モデルへのアクセスを信頼する」を有効にしておくことを必須とします。無効の場合、VBAを扱う操作は明確なエラーで拒否します。xlwrightはこの設定を変更しません。
- 主ブックは`.xlsm`と`.xlsx`を対象とします。`.xlsx`ではVBAの反映とマクロ実行を拒否し、ブックの編集だけを行います。
- アプリのフォルダは、主ブック・VBAソース・テストの置き場の規約に従います（[設計](architecture.md#アプリのフォルダ)）。
- アプリのフォルダは、ローカルのドライブに置きます。ネットワーク上のパス（UNC）は対象外とし、開始時に拒否します。パスを確かめるだけでネットワークへ接続し、認証情報を送る恐れがあるためです。
- xlwrightは、アプリのフォルダの中の`.xlwright/`に、実行時の状態を置きます（[設計](architecture.md#アプリのフォルダ)）。アプリのリポジトリは、このフォルダをGitの管理から外します。
- VBAソースはUTF-8で書き、コメント等に日本語を使えます。反映時にシステムのANSIコードページ（日本語環境ではCP932）へ変換します。変換できない文字を含むソースは反映を拒否し、ファイルと行を返します。AIエージェントには、変換できる文字だけでソースを書くよう求めます。
- マクロが出すダイアログへの事前の応答は、マクロがxlwrightの決めた書き方でダイアログを出す時だけ働きます。ほかのダイアログには答えません。マクロはそのダイアログで止まり、xlwrightが実行時間の上限で打ち切ります。既存のブックから取り出したソースも、この書き方に直す必要があります。
- この書き方のために、xlwrightが用意するVBAの関数がアプリのソースに入り、出来上がった主ブックにも残ります。xlwrightを使わない実行では、標準のダイアログを出します。
- 開発するアプリのリポジトリは、非公開で運用します。シートとブックの保護のパスワードは秘密として扱わず、平文でソースに書けます。
- ActiveXコントロールは非対応とします。作成・編集・実行の動作保証は提供しません。これは非対応方針であり、ActiveXの自動検出・実行防止を保証するものではありません。
- ツールを事前に許可するため、AIエージェントが書いたマクロは、人の承認なしに実行されます。
- xlwrightで実行するマクロとテストは、アプリのフォルダの外のファイルを変更しません。読むことは限りません。AIエージェントには、そう書くよう求めます。xlwrightは強制しません。

## 安全性と結果の要件

- 結果不明と明確な失敗を区別します。結果不明の要求を自動再送しません。
- 部分的に変更された操作を成功として報告しません。原子性や自動ロールバックは保証しません。
- [目標](#目標)の3で片付けてよいとしたもの以外のExcelを終了しません。片付ける時は、保存していない変更を捨てます。
- 専用のExcelの中でも、テストの中でも、VBAは人と同じ権限で動きます。xlwrightはその副作用を隔離しません。
- 組織のセキュリティ設定やVBAプロジェクトの保護を迂回しません。
- セル値やVBA全文を無条件にログへ出しません。

仕組みの方式は[設計](architecture.md)に書きます。具体的な制御と限界は、各段階で定めます。
