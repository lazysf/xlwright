# 0015: 結果不明では専用のExcelを終えてセッションを閉じる

- Status: Accepted

2026-11-02にユーザーが承認しました。
結果不明の時は、専用のExcelを終えてセッションを`closed`にし、`STATE_UNKNOWN`を返します。
期限切れの時は、このセッションで所有を確定した専用のExcelを、同一性を照合して終了させます。
所有を確定した後のCOMの切断では、プロセスが残っていれば、残った専用のExcelの片付けと同じ照合を通してから終えます。
公開する状態は`closed`と`ready`の2つで、実行中を`busy`で表します。
終了を確かめられない時と照合できない時は、所有記録を残して排他を外し、止まって知らせます。保留中のCOM呼出しが残る時は、排他を外さず、この会話を閉じてから新しい会話で開始するよう求めます。

## 背景

- 要件の目標の3は、実行時間の上限を過ぎた時に、今の会話が使う専用のExcelを、応答しなくても終了してよいとしています。
- 開いているブックを照合せずに終了してよいと要件が許すのは、この場合だけです。切断の後もプロセスが残っている場合は、片付けの条件（アプリのフォルダの中のブックだけを開いていると確かめられること）に従います。

## 検討した代替案

前の設計の`isolated`の状態を比べました。
結果不明の後は以後の操作を拒否し、人の手動復旧とサーバーの再起動を待つ形です。
新しい要件は、異常時もAIエージェントが片付けて作業を続けることを求めています。`isolated`は、この目標と合いません。
状態が1つ増え、各ツールの受付の判定も増えます。

## 影響

- AIエージェントは、`STATE_UNKNOWN`を受け取ったら、開始し直せる時は開始し直して作業を続けます。それ以外の時は、応答の手順に従います。結果不明の要求は自動で再送しません。
- 保存の途中で終了させると、主ブックのファイルが保存の前と後のどちらの内容かは分かりません。
- 保留中のCOM呼出しがある時に終了させた場合の挙動は、未確認です（[設計](../architecture.md#状態と結果不明)）。
- 保留中のCOM呼出しが残る時だけは、このサーバーで開始し直せません。この時は、前の設計の`isolated`と同じ扱いになります。
- `STATE_UNKNOWN`は、専用のExcelを終えた場合と、残して止まった場合の両方で返ります。応答で、この2つと、開始し直せるかを区別します。
