# 0001: 初期ライフサイクルは単一の所有記録と手動復旧を使う

- Status: Superseded
- Superseded-By: 0011

T2の実行プランは2026-10-29にユーザーが承認しました。
初期経路は排他兼用の単一ファイルを維持し、起動印・所有確定・完了の境界でだけ更新します。
公開の破棄終了・force・残存Excelの自動後始末は後送りし、異常時は手動復旧と新サーバーを使います。

## 比較と理由

比較対象は、保持ハンドルでの更新、排他と記録を別ファイルに分けた置換、同一ファイルへの追記です。
単一ファイルは既存の排他設計と.NET標準機能を使え、別ファイル間の整合制御や履歴解釈を増やしません。
更新途中に所有情報が欠けた場合、開始拒否と手動確認で対処する限界を受け入れます。
完全な追跡保持が必要になれば別ファイル案を再比較します。原子的更新やクラッシュ耐性を実証した判断ではありません。

## 影響

起動印は、公開状態とは別の復旧証拠として永続化します。
終了未確認時は記録を保持し、Protected Viewの存在・確認不能時は自動終了を拒否します。
詳細契約は設計（`bdd2bb4`時点の`docs/architecture.md`。削除済み）とAPI（`bdd2bb4`時点の`docs/api.md`。削除済み）を参照してください。
検証ケースはSpike-0（`bdd2bb4`時点の`docs/spike-0.md`。削除済み）にあります。
