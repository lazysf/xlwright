T3の[環境・依存の確認結果](notes/verification-environment.md)に、初回コンソールで参照する既存PIAの固定版・ハッシュと承認範囲を記載しています。

## 作業と検証

1. 正式文書の該当箇所と受け入れ条件を確認します。
2. 実機依存の仮説は[Spike-0](spike-0.md)で確認します。
3. その結果に基づいて、対象工程のコードと必要なテストを追加します。
4. 対象のテストと [prekのチェック](../README.md#開発時のチェック) を実行します。
5. 差分を確認し、基準フィクスチャや対象外ファイルへの意図しない変更がないか検査します。
6. 実装後の使い方と確認済みの制約を文書へ反映します。

検証コードを含め、依存パッケージは採用時にバージョンを固定します。
直近の実験に必要な依存から選び、MCP SDKの選定をコンソール検証の前提にはしません。
Spikeで本体全体や汎用検証基盤を先に作りません。
検証済みの処理は必要な部分をCoreへ移し、再現に必要な小さな実験は残します。一律の再実装は要求しません。
Excelの起動や設定変更を、通常の静的チェックに混ぜないでください。
実機検証には、使用するブックと変更・終了する対象を明示します。

## 初回コンソールの非COMチェック

リポジトリルートから実行します。このコマンドはExcelを起動しません。

```powershell
./spikes/Spike0/check.ps1
```

スクリプトはローカル設定でrestoreし、Debug・Releaseをビルドして、Releaseの`--self-check`を実行します。
パッケージ配布元は空です。子プロセスのCLIホーム・APPDATA・キャッシュは`.xlwright/spike0-build/`に限定します。
SDKの開発証明書生成を抑止します。呼出し元の環境変数を変更しません。
確認した結果と限界は[準備記録](notes/spike-0-preparation.md)を参照してください。
ビルド済みの自己チェックだけを実行する場合は、次を使います。

```powershell
dotnet spikes/Spike0/bin/Release/net10.0-windows/Spike0.dll --self-check
```

## 初回コンソールの実機実行

以下の正常系手順はユーザーによる実行の診断・保存ファイル・終了確認で検証しました。
エージェントからの実行はCOM生成時のアクセス拒否で失敗しました。現在はstarting記録を保持しているため、そのまま再実行しません。再開条件は[実機結果](notes/spike-0-results.md#現在の状態と再開条件)を参照してください。
対象と操作範囲の承認を得てから、対話可能なコンソールで実行します。

```powershell
dotnet spikes/Spike0/bin/Release/net10.0-windows/Spike0.dll --excel
```

操作範囲は次のとおりです。

1. `.xlwright/spike0/.xlwright.lock`を排他保持し、既存記録を検証します。未完了・不正・残存・同一性不一致なら生成せず拒否します。
2. `tests/fixtures/lifecycle.xlsx`を`.xlwright/spike0/runs/<run-id>/lifecycle.xlsx`へコピーします。基準ブック自体はExcelで開きません。
3. 起動印を確認してから専用Excelを生成し、Hwndから得たPID・生成時刻・プロセス名を確認します。既存ExcelのPIDなら操作を止めます。所有記録の確認後にコピーを開きます。
4. コピーの`Lifecycle!A2`を数値0から1へ変更し、読み戻して保存します。
5. 同一性、全ブックのパス、Protected View不在を確認します。保存しないClose後に再確認してQuitし、COM参照解放後に対象プロセスの終了を確認します。
6. 完了記録を確認して排他を解放します。保存ファイルのA2と基準ブックのハッシュを確認します。

既存ExcelへのCOM接続、プロセスの強制終了、設定の恒久変更は行いません。
開始・終了は各120秒、セル操作は30秒を上限とします。EOF等の終了要求も受理から120秒以内とし、保留呼出しの復帰待ちを含めます。無応答の呼出しを停止できる保証ではありません。
標準入力の`status`はCOMなしで状態を出力します。`stop`・EOF・Ctrl+Cは通常列を止める要求です。
入力を閉じるとEOFになるため、正常系の実行では入力を開いたままにします。
実行中のCOMが戻るまでは新しい後始末を投入しません。戻った後、時間切れでなく所有を確認できる場合だけ、保存せず安全確認付きの終了を試みます。

終了コード0はコピーの変更・保存・対象終了・記録完了・保存ファイル検査の成功です。
1は失敗または終了要求による中断、2は操作の期限切れによる結果不明です。
診断は実行ディレクトリの`diagnostics.jsonl`と標準出力へ出します。
ExcelのPID等の所有情報と失敗段階を確認します。セル内容を一般に収集するログではありません。

失敗・結果不明なら自動再送しません。記録を削除するだけで再実行しません。
起動途中の停止や失敗時は、イベント・警告等のインスタンス設定が復元されない可能性があります。
[手動復旧](architecture.md#初期の手動復旧)に従い、旧コンソールの終了を確認してから、人が対象Excelと未保存内容を確認します。
所有不明なら推測で終了しません。記録の整理や残存確認は、別途対象を示して行います。
実行後は対象プロセス・所有記録・診断、基準ブックのハッシュとGit差分を確認します。
観測は[Spike-0の記録方法](spike-0.md#結果の残し方)に従って残します。正常系だけでT5全体を完了にはしません。

## 実行時の生成物

`.gitignore` は .NETの `bin/`・`obj/`・`TestResults/` と、xlwrightの `.xlwright/`・`.xlwright.lock`・`dist/` を除外します。
基準ブックとVBAソースは除外しません。
検証結果を文書に残すときは、ログ全文をそのまま転載せず、必要な観測結果を記録してください。
