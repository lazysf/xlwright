## 作業と検証

### 非COM検証の自動実行

通常のビルドと非COM検証は、エージェントがリポジトリ直下で`npm run check`を実行します。
既存実験の再送・復旧・実Excel操作の承認条件は変更しません。
通常ユーザー側ではNode.js 26.13.0とnpm 11.20.0を確認しました。
sandbox側で指定版が見つからない場合は、正式な権限経路で実行します。
実行ポリシーは変更しません。

入口は[scripts/development.ps1](../scripts/development.ps1)です。
Windows PowerShell 5.1で既存の2本のcheck.ps1を`-Isolated`付きで実行します。
Debug・Releaseの出力と中間ファイルは`.xlwright/development/artifacts/`へ置きます。
接続中サーバーが使う通常のbin・objは更新しません。
続けてInspector CLIでツール一覧と読取り専用の`dev_status`を検証します。
最後にMarkdownチェックと`git diff --check`を実行します。
失敗時は後続工程を実行しません。

実行結果は`.xlwright/development/runs/<run-id>/result.json`と工程別の標準出力・標準エラーログへ保存します。
通常はキャッシュだけで依存を復元します。
キャッシュが不足する場合は、承認された取得範囲を確認して`npm run check -- -Restore`を実行します。
Nodeパッケージの準備には既存の`npm ci`を使います。
各`-Isolated`チェックは同じ出力先を使うため、統合入口から順番に実行してください。

### Inspectorによる調査

`npm run check`の後、リポジトリ直下で次を実行します。

```powershell
npm run inspect
```

Inspector 2.13.0のCLIがツール一覧をJSONで出力して終了します。
CLIの標準引数をそのまま渡せます。読取り専用の状態確認は次のとおりです。

```powershell
npm run inspect -- --method tools/call --tool-name dev_status
```

通常の検証はCLIで完結します。
必要なときだけ`npm run inspect:web`でGUIを起動します。
画面でxlwrightへ接続し、Toolsから引数・応答を確認します。
ProtocolでJSON-RPC、Consoleでサーバーの標準エラーを調査できます。
起動と`dev_status`はExcelを操作しません。
Excel開始ツールを使う場合は、既存の実験の対象・承認・再送禁止条件に従ってください。

[scripts/inspector.mjs](../scripts/inspector.mjs)は公式CLI・GUIへの薄い起動処理です。
標準機能の`--config`による読取り専用設定を使います。
起動ごとにサーバーとSpikeのビルド一式を`.xlwright/development/inspector/<session-id>/`へコピーします。
Inspectorが参照するDLLと次のビルド先を分けるため、GUIへ接続したまま`npm run check`を実行できます。
コピー中は統合ビルドと排他します。競合した場合は片方の完了を確認してから実行してください。
既存GUIの接続先は起動時のコピーです。新しいビルドを調査するときはGUIを終了し、`npm run inspect:web`を起動し直します。
終了するときはサーバーをDisconnectしてから、起動したターミナルでCtrl+Cを押してください。
`npm ci`などで依存を入れ直すときも、先にInspectorを終了してください。
WindowsではGUIが読み込んだネイティブモジュールの削除を拒否されることを確認しています。

`XLWRIGHT_DEVELOPMENT_SPIKE_DLL`は開発モード専用のSpike DLL指定です。
起動処理がコピー先を設定します。省略時は従来のRelease DLLを使います。
指定先はリポジトリ内に限定し、reparse pointを拒否します。
作業ディレクトリと実機の所有記録・ガードは同じリポジトリを使います。
コピーしたDLLを、Excelや作業データの隔離とは扱いません。

Inspectorの状態とログはセッションごとにリポジトリ内へ置きます。
secret storeはmemoryを指定し、個人のcredential storeを使いません。
GUIは127.0.0.1へbindし、標準の起動ごとの認証を有効にします。
起動URLやProtocol・Consoleにはローカル情報が含まれるため、出力をそのまま共有しないでください。

CLIの検証は接続ごとに1要求を実行して終了します。
非同期実験の開始と状態照会を、別々のCLI呼出しで行わないでください。
接続を維持するGUIか、既存の実機手順を使います。

InspectorはCodexへ登録した`xlwright-dev`とは別のサーバーを起動します。
Codexのツール選択や一連の操作は、直接MCP接続で別に確認します。
直接接続のDLL更新は[登録と更新](#登録と更新)に従って、アプリ通常終了・ビルド・再起動を行います。
Hotloadによる自動差替えは採用しません。

T10の準備コードとユーザー実行手順は[S9の固定ケース](../tests/fixtures/s9/README.md)を参照してください。
Excelなしの制御COM試験は通常チェックと別の専用CLIです。ユーザー実行の7ケースとビルド・チェックは通過しました。[実測と限界](notes/spike-0-results.md#t10の制御com試験2026-10-31)を参照してください。
ユーザー実行のビルド・Excelなしチェックは通過しました。[確認範囲](notes/spike-0-results.md#t10のビルドexcelなし確認2026-10-31)を参照してください。

1. 正式文書の該当箇所と受け入れ条件を確認します。

## 初回コンソールの非COMチェック

リポジトリルートから実行します。このコマンドはExcelを起動しません。

```powershell
./spikes/Spike0/check.ps1
```

スクリプトはローカル設定でrestoreし、Debug・Releaseをビルドして、Releaseの`--self-check`を実行します。
パッケージ配布元は空です。子プロセスのCLIホーム・APPDATA・キャッシュは`.xlwright/spike0-build/`に限定します。
SDKの開発証明書生成を抑止します。呼出し元の環境変数を変更しません。
確認した結果と限界は[準備記録](notes/spike-0-preparation.md)を参照してください。
ビルド済みの自己チェックだけを実行する場合は、次を使います。

```powershell
dotnet spikes/Spike0/bin/Release/net10.0-windows/Spike0.dll --self-check
```

L2・L3の追加自己チェックは、合成した所有記録と終了安全確認の観測値を使います。
記録I/Oの各境界の失敗、部分書込み、読戻し不一致、管理外ブック等の拒否と後続処理の抑止が対象です。
実機の所有記録・ガード・復旧証拠は使用しません。Excelも起動しません。
証拠は`.xlwright/spike0-checks/<run-id>/`に保持します。
記録I/Oケースの`.failure.json`は失敗境界と状態、`.retained`はハンドル解放後の残存バイト列です。
終了拒否ケースの`.observation.json`は呼出し順と状態です。
チェック失敗時はこのディレクトリとコマンド出力を保持し、自動再送せず引き継ぎます。
合成ファイルの排他解放を、実Excelの終了や実機所有記録の完了とは扱いません。
追加コードのビルド・実行状況は[結果記録](notes/spike-0-results.md#l2l3の非com検証準備)を参照してください。

## 初回コンソールの実機実行

以下の正常系手順はユーザーによる実行の診断・保存ファイル・終了確認で検証しました。
直接のエージェントシェルではCOM生成のアクセス拒否を観測しました。T5では、手動復旧後のユーザー実行と、MCP経由の固定コンソール実行で次回開始まで確認しました。現在の実測範囲と再開条件は[実機結果](notes/spike-0-results.md#現在の状態と再開条件)を参照してください。未完了記録がある場合は、そのまま再実行しません。
対象と操作範囲の承認を得てから、対話可能なコンソールで実行します。

```powershell
dotnet spikes/Spike0/bin/Release/net10.0-windows/Spike0.dll --excel
```

操作範囲は次のとおりです。

1. `.xlwright/spike0/.xlwright.lock`を排他保持し、既存記録を検証します。未完了・不正・残存・同一性不一致なら生成せず拒否します。
2. `tests/fixtures/lifecycle.xlsx`を`.xlwright/spike0/runs/<run-id>/lifecycle.xlsx`へコピーします。基準ブック自体はExcelで開きません。
3. 起動印を確認してから専用Excelを生成し、Hwndから得たPID・生成時刻・プロセス名を確認します。既存ExcelのPIDなら操作を止めます。所有記録の確認後にコピーを開きます。
4. コピーの`Lifecycle!A2`を数値0から1へ変更し、読み戻して保存します。
5. 同一性、全ブックのパス、Protected View不在を確認します。保存しないClose後に再確認してQuitし、COM参照解放後に対象プロセスの終了を確認します。
6. 完了記録を確認して排他を解放します。保存ファイルのA2と基準ブックのハッシュを確認します。

既存ExcelへのCOM接続、プロセスの強制終了、設定の恒久変更は行いません。
開始・終了は各120秒、セル操作は30秒を上限とします。EOF等の終了要求も受理から120秒以内とし、保留呼出しの復帰待ちを含めます。無応答の呼出しを停止できる保証ではありません。
標準入力の`status`はCOMなしで状態を出力します。`stop`・EOF・Ctrl+Cは通常列を止める要求です。
入力を閉じるとEOFになるため、正常系の実行では入力を開いたままにします。
実行中のCOMが戻るまでは新しい後始末を投入しません。戻った後、時間切れでなく所有を確認できる場合だけ、保存せず安全確認付きの終了を試みます。

終了コード0はコピーの変更・保存・対象終了・記録完了・保存ファイル検査の成功です。
1は失敗または終了要求による中断、2は操作の期限切れによる結果不明です。
診断は実行ディレクトリの`diagnostics.jsonl`と標準出力へ出します。
ExcelのPID等の所有情報と失敗段階を確認します。セル内容を一般に収集するログではありません。

失敗・結果不明なら自動再送しません。記録を削除するだけで再実行しません。
起動途中の停止や失敗時は、イベント・警告等のインスタンス設定が復元されない可能性があります。
[手動復旧](architecture.md#初期の手動復旧)に従い、旧コンソールの終了を確認してから、人が対象Excelと未保存内容を確認します。
所有不明なら推測で終了しません。記録の整理や残存確認は、別途対象を示して行います。
実行後は対象プロセス・所有記録・診断、基準ブックのハッシュとGit差分を確認します。
観測は[Spike-0の記録方法](spike-0.md#結果の残し方)に従って残します。正常系だけでT5全体を完了にはしません。

## MCP起動機構の権限診断

`spikes/Spike0/InspectMcpLaunch.ps1`はPowerShell 7の一回限りの診断です。通常チェックとサーバー更新には使いません。
Excel・MCP初期化・ツール呼出しは行いません。MCP接続失敗は想定内です。
`-ExperimentId`にGUID、`-Route`に`user-shell`・`agent-shell`・`mcp-launcher`を指定します。
同じスクリプトと実験識別子で3経路を比較します。
この診断を再実施する場合は、利用できるシェルと実行経路を別途確認します。実行ポリシーは迂回しません。

記録は`.xlwright/mcp-launch-probe/<実験識別子>/<起動識別子>.json`に保存します。
整合性は標準`whoami.exe`の子プロセスから取得します。全グループは保存しません。
標準出力は空、標準エラーは起動識別子と測定成否だけです。
終了コード0は診断・保存の完了、1は失敗です。未知の結果をLow等に置き換えません。
`whoami`が10秒で終了しない場合は結果不明です。診断プロセスの終了だけで子プロセスの終了を確認したとは扱わず、人へ引き継ぎます。
記録にはプロセス同一性が含まれます。個人パスを含む登録用情報もGit管理外に置きます。

両シェルの測定成功後に、ユーザーがアプリの「設定 → プラグイン → MCP」へ専用名`xlwright-launch-probe`を一時登録します。
登録は確認済みPowerShell、`-NoLogo -NoProfile -NonInteractive -File`、診断スクリプトと引数、リポジトリ直下の作業ディレクトリを使います。
既存設定は変更しません。起動1回の後、アプリの標準エラーとJSONの識別子を照合します。
自動再起動がある場合は起動ごとの記録を残し、追加の手動再試行はしません。
測定後は専用登録を除去・再読込みし、記録されたプロセスの終了を確認します。
今回の画面では専用項目の「アンインストールする」で除去しました。登録時に記録が生成済みなら追加の起動は行いません。
登録拒否・追加権限要求・記録欠落・終了未確認なら停止します。
既存startingと基準ブックは変更しません。診断の成立をCOM生成やT5全体の合格とみなしません。
現在の結果は[実機結果](notes/spike-0-results.md#mcp起動機構の権限診断)を参照してください。

## 継続利用するMCP開発環境

[採用判断](adr/0002-development-mcp-foundation.md)に基づくstdio接続基盤です。
引数なしでは開発用ツールを公開せず、リポジトリ探索やExcel操作を行いません。製品のExcel操作APIは未実装です。
`--development`で起動すると、下記の7ツールだけを公開します。作業ディレクトリはリポジトリ直下、起動は確認済み`dotnet.exe`とビルド済みDLLを使います。
アプリからの接続・更新・再接続と実Excelの成立性は、ローカルの非COM検証とは別に確認します。

| ツール | 入力と結果 |
| --- | --- |
| `dev_status` | 入力なし。起動識別子、サーバーとSpike DLLのSHA-256、受付識別子、状態、終了コード、直近の観測、相対ログ先 |
| `dev_excel_smoke_start` | 入力なし。既存Spike0の固定`--excel`を1回開始し、受付識別子を含む状態を返す。実行範囲の事前承認が必要 |
| `dev_excel_end_refusal_start` | 入力なし。固定L3ケースを1回開始する。主コピーと管理外コピーを同じ専用Excelで開き、終了拒否を観測する。事前承認が必要 |
| `dev_excel_record_fault_starting_start` | 入力なし。固定L2ケースSを1回開始する。startingの書込み前に失敗を注入し、Excelを生成しないことを観測する。事前承認が必要 |

### 証拠・副作用・停止

既存の`.xlwright/spike0/`と所有記録、MCP共有ガードを使います。
T8は既存所有記録completedを要求します。s1.attempt等を作り、同じケースの再送を拒否します。
s2以降は前ケースのattemptとsuccessの非空・内容一致を要求します。T7の印は使いません。
正常な保存・終了・保存ファイル検査・基準ハッシュ検査後だけsuccessを作成します。
印の読戻しと自分のガードの照合後だけ、そのガードを除去します。

runにはコピー、diagnostics.jsonl、cell-build.json、cell-observations.json、saved-sheet.xmlを保持します。
ビルド情報はDLL・関連ソースのハッシュと実行ランタイムを含みます。SDK版は上記ユーザー出力を記録します。
診断は照合前のセル値・型・数式・PrefixCharacter・NumberFormat、配列の形状と下限、S2の書式を含みます。
保存XMLはライブ観測の値・型と照合します。保存数式の存在も確認します。
再Open後のCOM読取りや保存数式全文の同一性を保証する検査ではありません。

実行コードにVBA、外部リンク、ネットワーク関数、外部プログラム起動は含みません。
書込み先は上記証拠と既存の所有記録・共有ガード・実行印・成功印です。
ビルドは既存のbin・obj・ローカルキャッシュを更新します。Excelの通常の一時ファイル生成まで隔離しません。

終了コード0と最後のcell.completed、保存検査、印と所有記録、ユーザー側の終了確認を照合します。
1は失敗、2は期限超過による結果不明です。セル操作はケース全体30秒、開始・保存・終了は各120秒です。
仮説不一致・COM失敗・結果不明では追加COM操作と後続ケースを止めます。
意図したセルエラーはCOM失敗と区別します。失敗後に保存や自動の代替方式へ進みません。
statusはCOMなしの状態照会です。stop・EOF・Ctrl+Cは終了要求であり、COM停止の保証ではありません。
停止後のコピー・印・ガード・所有記録・診断は保持します。
手動復旧は[初期の手動復旧](architecture.md#初期の手動復旧)に従い、対象と証拠を示して別途承認を得ます。
T7・ケースO・過去の復旧スクリプトは再実行しません。
結果文書に個人パス・実PID・ログ全文を転記しません。

### S4失敗後の保存再評価と限定整理

保存検査は、今回観測したRichDataのSPILL・CALC表現に対応する修正を追加しています。
セルのvm、valueMetadata、metadataTypes、futureMetadata、rich value、構造のキーと値を順に照合します。
参照欠落・不正index・型不一致・未対応errorTypeを通常の#VALUE!へ置き換えません。
合成チェックはSPILL・CALC、キー順の違い、参照不正・欠落、型・キー不一致、未知種別、値数不一致を対象にします。
2026-10-30 19:54 JSTのユーザー提示出力で修正版のビルド・チェック通過を確認しました。自己チェック58件、MCP非COM58件、Markdown 20ファイルの問題0件で、各終了コードは0でした。
19:57 JSTに固定コピーの非COM再評価が終了コード0で通過しました。元実験の終了コード1は保持しています。再評価入口も再実行しません。限定整理は19:58 JSTに個別承認で完了しました。

`--verify-s4-saved`は固定run `7782619e5a6749e0bd1b39f3c085836e`だけをExcelなしで再評価する入口です。
ブックと観測JSONの固定ハッシュを検査し、読取り専用ハンドルで書込み・削除を拒否して検証します。
元runへは書き込みません。元の診断・終了コード1、所有記録、ガード、attempt、successを変更しません。
再評価結果は`.xlwright/spike0/recovery/s4-7782619e5a6749e0bd1b39f3c085836e/saved-recheck.json`へ新規作成します。
既存結果があれば再評価を拒否します。成功時も元実験の終了コードを0へ変更しません。

今回専用の`Recover-S4.ps1`と固定8ファイルのmanifestを同じrecoveryディレクトリに準備しています。
このスクリプトの実行は別途承認が必要です。アプリを通常終了してからユーザーの通常PowerShellで実行します。
元の起動記録・診断にあるMCP・コンソール・Excelの各PID不在と、Excel・xlwright全体の不在、所有記録とガードの排他を確認します。PID再利用を含む残存・照会不能では停止します。

ガードを保持したまま、アプリ通常終了・旧サーバー不在の条件でユーザーが両check.ps1とMarkdown lintを実行します。

Excel再実験なしで保存証拠を再評価し、ライブ観測・後始末と合わせてS4の判定を整理します。
