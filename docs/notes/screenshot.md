# ブックの見た目を画像にする

- Date: 2026-11-17
- 出典: 一時フォルダの新しい `.xlsx` で、実験用スクリプトを流した実測。Microsoft 365 Excel 64-bit 16.0.20527.20196（日本語の表示、Office のテーマは黒）、Windows 11、Windows PowerShell 5.1.26100.9818（STA）、画面の拡大率 100%（96 dpi）。Excel は `Use-ExcelWorkbook` で起動した。

作ったツールが人にどう見えるかを確かめるために、ブックの見た目を画像にする方法を比べた。人が見る画面に最も近いのは、Excel を画面に出してウィンドウを `PrintWindow`（`PW_RENDERFULLCONTENT`）で撮る方法だった。非表示の Excel では、ウィンドウは撮れなかった。

## ウィンドウを PrintWindow で撮る

### 手順

1. シートに、赤で塗ったセル、条件付き書式、横棒グラフ、フォームのボタンを置き、セルを塗った 2 枚目のシート `Far` を足す。
2. Excel のウィンドウ（`Application.Hwnd`）を `GetWindowRect` の大きさの画像に `PrintWindow` で撮る。非表示のまま、画面に出して最大化したまま、`WindowState` を `xlNormal` にして 900 × 600 pt にした時、拡大率 150%、`Application.Goto` で `Far!AA200` に動いた後、画面の外（`Left = -3000`）、最小化、の順に撮る。
3. 別に、非表示のまま `WindowState`、位置、大きさを決めてから `Visible` を `True` にし、時間を置いて撮る。
4. 前面のウィンドウのプロセスを 50 ms ごとに記録した。クリップボードには前もって文字列を置き、終わった後に読んだ。

### 結果

| 状態 | 結果 |
| --- | --- |
| 非表示 | `true` を返したが、画像は全面が黒だった |
| 画面に出した（最大化、900 × 600 pt、拡大率 150%） | リボン、数式バー、セル、塗り、条件付き書式、グラフ、ボタン、シートの見出し、状態バーが、画面と同じに写った |
| 画面の外（`Left = -3000`） | 画面の中と同じに写った |
| 最小化 | タイトルバーだけの 160 × 28 の画像になった |

- 前面にいない Excel のウィンドウも撮れた。1 回は 20〜52 ms だった。
- 900 × 600 pt のウィンドウは、1200 × 800 px の画像になった。
- `Application.Goto` で別のシートの `AA200` に動くと、すぐ後に撮った画像で `Far` が選ばれ、`AA200` が左上にあった。`ScrollRow` は 200、`ScrollColumn` は 27 だった。
- 非表示のまま `xlNormal` にし、`Left` を -3000 にしてから `Visible` を `True` にすると、ウィンドウは画面に出ないまま撮れた。その間、前面は一度も Excel にならず、クリップボードの文字列も変わらなかった。
- `Visible` を `True` にした 200 ms 後の画像では、シートの見出しの帯が描かれていなかった。1 秒後の画像では描かれていた。
- 画面に出したままウィンドウの大きさを変えた直後の画像では、リボンの文字が重なって描かれていた。
- 最大化から順に状態を変えた実験では、前面が 4 回（約 200 ms）Excel に移った。どの操作で移ったかは記録していない。画面の外から始めて最小化しなかった実験では、移らなかった。
- 画像には、Office のテーマとアカウントの頭文字が写った。人の環境の見た目がそのまま写る。

`Test-RibbonLayout.ps1` も、画面に出した Excel のリボンを同じ方法で撮っている。画面に出しても前面を変えないことは [foreground.md](foreground.md) にある。

## Range.CopyPicture でセルの範囲を撮る

非表示の Excel で、`Range.CopyPicture` でクリップボードに写した範囲を PNG にした。列挙の値は、Microsoft の `Range.CopyPicture`、`XlPictureAppearance`（`xlScreen` が 1、`xlPrinter` が 2）、`XlCopyPictureFormat`（`xlBitmap` が 2、`xlPicture` が -4147）の文書で確かめた（2026-11-17）。文書は、範囲をクリップボードに写すとだけ書き、大きさの上限、離れた範囲、非表示のウィンドウについては書いていない。

| 方法 | 非表示の Excel での結果（各 5 回） |
| --- | --- |
| `CopyPicture(1, 2)` の後 `System.Windows.Forms.Clipboard.GetImage()` | 塗り、条件付き書式、表示形式、グラフ、列幅が写った。1/5 は `GetImage()` が `null` だった |
| `CopyPicture(1, -4147)` の後、`ChartObject` に `Chart.Paste()` して `Chart.Export` | 5/5 で、枠だけの白い画像になった |
| `CopyPicture(2, -4147)` の後、同じく `Chart.Export` | 1/5 だけ写った |

`CopyPicture(1, 2)` について、次のことが分かった。

- 画像の大きさは、範囲の pt を 96/72 倍した値になった。写るのはセルと、範囲に重なったグラフだけで、リボンやシートの見出しは写らない。
- 30 回続けて呼ぶと、7 回で最初の `GetImage()` が `null` だった。100 ms 待ってやり直すと、3 回目までにすべて読めた。
- 作業中でないシート、非表示のシート、`veryHidden` のシートも撮れた。隠した行は写らなかった。
- 高さは 32766 px で止まった（`A1:AZ2000` で 3745 × 32766）。
- 離れた範囲は `COMException`「この操作は複数の選択範囲に対しては機能しません。」になった。
- 呼んだ後、クリップボードには画像が残り、前に置いた文字列は消えた。

クリップボードの前の中身を、`Clipboard.GetDataObject()` で形式ごとに写し取り、撮った後に `DataObject` に入れて `Clipboard.SetDataObject` で戻せるかも調べた。

- 文字列、画像、ファイルの一覧、HTML と文字列の組は、戻せた。
- Excel の `Range.Copy` で置いた中身（24 形式）は、写し取れた。戻すと、`SetDataObject` で PowerShell が `OLE32.dll` の例外 `0xc000041d` で落ちた。`EnhancedMetafile` と `MetaFilePict` を外しても落ちた。PowerShell が落ちると、Excel は watchdog が止めるまで残った。
- 戻す形式を `UnicodeText`、`Text`、`HTML Format`、`Rich Text Format`、`Csv`、`FileDrop`、`FileNameW`、`FileName`、`Bitmap` に絞ると、Excel の中身も 3 回とも落ちずに戻せた。セルとして貼る形式（`Biff12` など）は失われた。

人に見える形が写らず、人のクリップボードを書き換えるので、見た目の確認には使わない。

## Save-WorkbookScreenshot.ps1 の形にした理由

使い方の正本は `plugins/xlwright/skills/xlwright/references/com.md` の「見た目を画像にする」にある。

- **ウィンドウを `PrintWindow` で撮る。** 人が見る画面に最も近く、クリップボードを使わない。`CopyPicture` は上のとおり、セルしか写らず、人のクリップボードを書き換える。
- **非表示で開き、画面の外に置いてから表示する。** `Use-ExcelWorkbook -Visible` は開く前に表示するので、ウィンドウが一度画面に出る。置く位置は、`GetSystemMetrics(SM_XVIRTUALSCREEN)` で得た、すべての画面を合わせた範囲の左端より、ウィンドウの幅と 100 px だけ左にする。
- **表示してから 1 秒待ち、その後にシートを選んで `Goto` する。** 200 ms では、シートの見出しの帯が描かれていなかった。
- **ウィンドウの大きさを px で受け、pt に直して渡す。** 画像の大きさは px なので、受け取る値をそろえた。画面の拡大率が 100% でない時の換算は確かめていないので、警告を出す。
- **非表示のシートは失敗にする。** 確かめを外した写しでは、非表示のシートを渡しても `Activate` は失敗せず、終了コード 0 で画像を保存した。人がブックを開いても見えないシートなので、写しても見た目の確認にならない。

`plugins/xlwright/skills/xlwright/tests/Test-XlWright.ps1` の `screenshot`（`-Full`）が、これを確かめる（2026-11-17）。画像の色は、リボンのアイコンにない純粋なマゼンタと緑の塗りで数える。赤はリボンのアイコンとアカウントの表示にも使われていた。何を確かめるかは、試験のファイルを正本とする。

- スクリプトをわざと壊した次の写しは、どれも `screenshot` で落ちた。表示しない写し、`-Range` に動かない写し、`-Sheet` を選ばない写し、幅を決めない写し、非表示のシートを拒まない写し。
- 表示した後に待たない写しと、画面の外に置かない写しは、この試験では見分けられない。前者は描きかけの画像を、後者は画面に出るウィンドウを生む。
