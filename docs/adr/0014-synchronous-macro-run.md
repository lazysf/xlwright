# 0014: マクロとテストの実行を、終わるまで応答を待つ形にする

- Status: Accepted

2026-11-02にユーザーが承認しました。
`macro_run`と`test_run`は、実行が終わるか上限を過ぎるまで応答を待ちます。
受付のIDを返して状態を照会させる形は作りません。
実行時間の上限は、1回の呼出しの全体で測り、Claude Codeの30分の無応答の打ち切りより短くします。値は[設計](../architecture.md#期限と大きさの上限)で定めます。

## 背景

Claude Codeの公式の文書（[MCP](https://code.claude.com/docs/en/mcp.md)、2026-11-02に確認）には、次のようにあります。

- MCPのツール呼出しの上限は、既定で約28時間です。
- stdioのサーバーへの呼出しは、30分の間、応答も進捗の通知も無いと打ち切られます。
- 2分を超えた呼出しは、会話のバックグラウンドの作業へ移ります。

## 検討した代替案

前の設計の、受付のIDを返し、AIエージェントが状態を照会して結果を受け取る形を比べました。
この形は、クライアントが長い呼出しを待てない場合に要ります。
上の事実から、Claude Codeは長い呼出しを待てます。この形にすると、ツールが1つ増え、IDの管理と照会の手順が要ります。

## 影響

- 実行中も、`session_status`はCOMを使わずに状態と経過時間を返します。実行の間にAIエージェントが照会を送れるかは、未確認です。
- Claude Codeの上限や、無応答の打ち切りの扱いが変わった時は、この判断を見直します。
