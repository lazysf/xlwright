# 0004: セッションをサーバープロセス単位に保ち、session_idを導入しない

- Status: Accepted

2026-11-01に、T14でユーザーが承認しました。
セッションはサーバープロセスごとに最大1つとし、MCPのプロトコルのセッションには依存しません。
製品ツールは`session_id`を引数に取りません。

## 背景

api.md（`bdd2bb4`時点の`docs/api.md`。削除済み）は「セッションはMCP接続ごとに1つ」と定めていました。
MCP 2026-07-28はプロトコルのセッションを廃止し、明示的なハンドルを引数で渡す設計を案内しています。この案内は非規範です。
詳細は[調査記録](../notes/mcp-best-practices.md#現在の実装との差)を参照してください。

## 検討した代替案

`session_start`がハンドルを返し、各操作がそれを受け取る案を比較しました。
stdioでは1つのサーバープロセスに1つのクライアントが接続します。
ハンドルを導入しても、サーバープロセスが終われば状態は失われます。
同じプロジェクトでのセッションは、`.xlwright.lock`の排他で1つに限る設計です。
ハンドルを加えると全操作に入力・検証・エラーが増えますが、stdioの範囲で得られる効果を確認できていません。

## 影響

接続を切ると、セッションはEOFの規則で後始末する設計です。
Inspector CLIは1要求ごとに接続を閉じるため、要求をまたぐセッションを検証できません。
要求をまたぐ検証には、接続を維持するクライアントを使います。
Streamable HTTPなど、1つのサーバープロセスへ複数のクライアントが接続する経路を加えるときは、この判断を見直します。
