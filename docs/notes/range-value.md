# セルの範囲を 2 次元配列で読み書きする

- Date: 2026-11-17
- 出典: 一時フォルダの新しい `.xlsx` で、実験用スクリプトを非表示の Excel で流した実測。Microsoft 365 Excel 64-bit 16.0.20527.20196（日本語の表示）、Windows 11、Windows PowerShell 5.1.26100.9818。PowerShell の束縛に関わる項目は、一度落ちた後の振る舞いを見た項目を除き、1 項目ごとに別の `powershell.exe` で流した。

`Range.Value2` などへ 2 次元配列を代入・読み出しする時に、どの形と型が通り、何が黙って変わるかを確かめた。

## 結果

### `Cells.Item` への代入が落ちる条件

以前の `SKILL.md` は、`$ws.Cells.Item(r, c).Value2 = 3` が `InvalidCastException` で落ちることがあり、`Range('B2')` の形なら通るとしていた。実際には、`Cells.Item` か `Range` かではなく、PowerShell の書き方で起きた。

| 書き方 | 結果 |
| --- | --- |
| `$ws.Cells.Item(1, 1).Value2 = 3`（整数のリテラル） | 通る |
| 同じ行の代入を、型の違う値で繰り返す（`foreach ($v in 'a', 1) { $ws.Cells.Item(1, 1).Value2 = $v }`） | `InvalidCastException`（`System.Int32` を `System.String` にキャストできない） |
| 同じ行で `1`、`'a'`、`2.5`、`$true` を `Range('A1').Value2` に代入 | `InvalidCastException` |
| `ConvertFrom-Json` の数値を `Value2` に代入した後、別の行で 2 次元配列を `Value2` に代入 | 後の配列の代入が `InvalidCastException`。それぞれ単独では通る |
| 一度落ちた後の同じプロセスの、別の行での配列の代入 | 続けて `InvalidCastException`。スカラーの代入と `Formula`、`Value` への代入は通った |
| 上の 3 つを `[System.__ComObject].InvokeMember('Value2', SetProperty, ...)` で代入 | どれも通った |

- 型の違う値を同じ行で代入すると落ちること、前の代入の型が後の別の行に響くことから、PowerShell が COM のプロパティの代入を束縛した結果を使い回していると推測する。仕組みは確かめていない。
- `InvokeMember` で代入すると、PowerShell の束縛を通らず、どの順でも通った。

### 書き込む配列の形

| 代入した値 | 結果 |
| --- | --- |
| `object[,]`（0 始まり、1 始まり） | どちらも通り、同じ結果 |
| `double[,]`、`string[,]` | 通る。`string[,]` は文字列の扱いが違う（下の「文字列」） |
| ジャグ配列（`object[]` の `object[]`） | 例外にならず、範囲の全セルが空になった |
| 1 次元の配列を 1 行の範囲へ | 横に並ぶ |
| 1 次元の配列を 1 列の範囲へ | 全セルが先頭の要素になる |
| 1 行、1 列、1 セルの `object[,]` | どれも通る |
| 配列より大きい範囲 | はみ出たセルが `#N/A` になる。行が 1 つなら、その行が下の行へ繰り返される |
| 配列より小さい範囲 | 範囲に入る分だけ書かれ、残りは黙って捨てられる |
| シートの端を越える範囲 | `Range('A1048576').Resize(2, 1)` が `0x800A03EC` で落ちる |

- PowerShell の関数から 2 次元配列を返すと、要素が平らに並んだ 1 次元の配列になった。`, $array` で返すと 2 次元のまま返る。

### 要素の型（`object[,]` を `Value2` へ）

| 要素 | セルの値（`Value2` で読み戻した型と値） |
| --- | --- |
| `$null`、`[DBNull]::Value` | 空のセル。前の値は消える |
| `''` | 空のセル。`CountA` は 0 |
| `[int]`、`[long]`、`[decimal]` | `Double` |
| `[sbyte]`、`[byte]`、`[int16]`、`[uint16]`、`[uint32]`、`[uint64]`、`[single]` | `Double`。どれも例外にならなかった |
| `[long]9007199254740993`、`[uint64]::MaxValue`、`[decimal]::MaxValue` | `Double` に丸めた値（`9007199254740992`、`1.8446744073709552E+19`、`7.9228162514264338E+28`）。例外にならない |
| `[bool]` | `Boolean` |
| `[datetime]` | シリアル値の `Double`（`2026-11-17 13:30` は `46343.5625`）。表示形式は標準のまま |
| `[char]'q'` | `113`（文字コード） |
| `[double]::NaN` | `#NUM!` |
| `[psobject]5`（PSObject で包んだ値） | `0x800A03EC`。`InvokeMember` でも同じ |
| `[guid]`、hashtable | `0x800A03EC`、`見つからないパラメーターには既定値がありません` |
| 配列（`object[]`） | 例外にならず空のセル |
| 300 字、9000 字の文字列 | そのまま |
| 40000 字の文字列 | 32767 字に切られた。例外にならない |
| 日本語の文字列 | そのまま |

- `ConvertFrom-Json` の数値を `object[,]` の要素に代入した時は通った。`[psobject]` で包んだ値を要素に代入した時は落ちた。
- `Value` へ同じ配列を代入すると、`[datetime]` のセルにだけ表示形式（`yyyy/m/d`、時刻があれば `yyyy/m/d h:mm`）が付いた。値は `Value2` と同じシリアル値。`[decimal]` には付かなかった。Microsoft の `Range.Value2` の文書は、`Value` との違いを Currency と Date の型を使わないことだけとしている（2026-11-17 に確かめた）。

### 文字列

`object[,]` の文字列は、人がセルに打ち込んだ時と同じように解釈された。`string[,]` の文字列は、先頭の `'` を除いて、文字のまま入った。

| 文字列 | `object[,]` | `string[,]` |
| --- | --- | --- |
| `001` | `1`（数値） | `001` |
| `1/2` | `46024`（今年の 1 月 2 日） | `1/2` |
| `=1+1` | 数式 `=1+1`、値 `2` | `=1+1`（文字） |
| `TRUE` | `True`（真偽値） | `TRUE` |
| `'abc` | `abc`、`PrefixCharacter` が `'` | 同じ |
| `''` | 空のセル | 空のセル |
| `1e3`、` 12 `、`50%` | `1000`、`12`、`0.5` | 文字のまま |
| `#N/A` | エラー値の `#N/A` | `#N/A`（文字） |

- 先頭に `'` を付けると、`object[,]` でも文字のまま入った。`'001` は `001`、`'=1+1` は `=1+1`、`''abc` は `'abc`。`Value2`、`Formula`、`Text` に `'` は出ず、`PrefixCharacter` が `'` になる。`'` を付けない `plain` は、`PrefixCharacter` が空のまま。
- `'` だけを代入したセルは、`Value2` が空の文字列になり、`CountA` は 1 だった。
- `'001` を入れたセルに、後から `5` や `'7'` を代入すると、`PrefixCharacter` は空に戻った。
- 表示形式を文字列（`@`）にしたセルへ `object[,]` で数値と日付を代入すると、`Double` のまま入った。
- `object[,]` で数式になったのは、先頭が `=` か全角の `＝`（U+FF1D）の文字列だけだった。どちらも代入した時点で計算され、`=1+1` も `＝1+1` も数式 `=1+1`、値 `2` になった。`=` だけの文字列は文字のまま入った。
- 先頭が `+`、`-`、`@` と、その全角（`＋A1`、`－A1`、`＠SUM(A1)`）の文字列は、数式にならなかった。`+1` と `-1` は数値になり、`+A1`、`-A1`、`-abc`、`@SUM(A1)` は文字のまま入った。
- `=` の前に空白、タブ、全角の空白、改行がある文字列（` =1+1` など）は、数式にならず、文字のまま入った。

### 数式

- `Formula` へ `object[,]` を代入すると、`=` で始まる文字列は数式になり、ほかの文字列は `Value2` と同じく解釈された（`001` が `1`）。`null` は空のセル。
- `Formula` へ `=SEQUENCE(2)` を代入すると、`Formula2` が `=@SEQUENCE(2)` になり、下へこぼれなかった。`Formula2` へ代入すると、下のセルへこぼれた。Microsoft の `Range.Formula2` の文書は、Dynamic Arrays のある Excel では `Formula2` が `Formula` に代わるとしている。対応する版は書かれていない（2026-11-17 に確かめた）。
- こぼれた先のセルの `Formula2` は空の文字列で、`HasSpill` は `True`。
- `Formula` を複数のセルで読むと、1 始まりの `object[,]` で、値だけのセルはその値の文字列、空のセルは空の文字列になった。1 セルでは文字列が返る。

### 読み出し

| 範囲 | `Value2` の戻り値 |
| --- | --- |
| 複数のセル（1 行、1 列を含む） | 1 始まりの `object[,]` |
| 1 セル | 配列でなく、その値（空なら `null`） |
| 複数のセルの空のセル | 要素が `null` |
| 離れた範囲（`A2:B3,D2:E3`） | 最初の範囲だけの `object[,]`。例外にならない |
| 結合したセル（`A1:B1`） | 左上だけに値があり、ほかは `null`。2 つの値を書くと、2 つ目は捨てられた |
| 保護したシート | 書き込みが `COMException`（保護を解くよう求める文言） |

エラー値のセルは、`Int32` で返った。下位 16 ビットが Microsoft の `XlCVError` の値になる。`Text` は表示の言語で変わり（`#SPILL!` は `#スピル!`）、列の幅が足りないと `#######` になる。

| 数式 | `Value2` | 下位 16 ビット | `Text` |
| --- | --- | --- | --- |
| `=NULL` 相当（`=A10 B10`） | -2146826288 | 2000 | `#NULL!` |
| `=1/0` | -2146826281 | 2007 | `#DIV/0!` |
| `="a"+1` | -2146826273 | 2015 | `#VALUE!` |
| `=#REF!+1` | -2146826265 | 2023 | `#REF!` |
| `=NOSUCHFN()` | -2146826259 | 2029 | `#NAME?` |
| `=SQRT(-1)` | -2146826252 | 2036 | `#NUM!` |
| `=NA()` | -2146826246 | 2042 | `#N/A` |
| `=#GETTING_DATA` | -2146826245 | 2043 | `#######` |
| こぼれる先がふさがった `=SEQUENCE(2)` | -2146826243 | 2045 | `#スピル!` |
| `=LAMBDA(x,x)` | -2146826238 | 2050 | `#CALC!` |

- Microsoft の `XlCVError` の文書にあるのは、2000、2007、2015、2023、2029、2036、2042、2045 の 8 つ（2026-11-17 に確かめた）。2043 と 2050 は文書に無く、上の実測だけ。

### 時間

すべて `Double` の値、または短い文字列。

| 大きさ | 一括の代入 | 一括の読み出し | 読み出しを行の配列に直す |
| --- | --- | --- | --- |
| 100 行 × 10 列 | 10 ms | 0 ms | 3 ms |
| 10000 行 × 20 列 | 900 ms | 60 ms | 102 ms |
| 100000 行 × 10 列 | 914 ms（文字列は 2590 ms） | 262 ms | 304 ms |

- 100 行 × 10 列を 1 セルずつ代入すると 2909 ms かかった。一括では 10 ms。
- 100000 行 × 10 列で、行の配列から `object[,]` を作って要素の型を確かめるのに 591 ms、`InvokeMember` での代入に 934 ms、読み戻しに 238 ms、文字列が読み戻しと一致するかの照合に 323 ms かかった。
- 1000 行 × 20 列の代入が 1 回だけ 571 ms かかった。1 回しか流していないので、ばらつきは分からない。

## Read-ExcelRange と Write-ExcelRange の形にした理由

使い方の正本は `plugins/xlwright/skills/xlwright/references/com.md` の「セルの範囲を読み書きする」にある。

- **読み出しは行の配列にする。** `Invoke-ExcelScript.ps1` の `ConvertTo-PlainValue` が 2 次元配列を行の配列に直す形とそろえ、`Read-ExcelRange` の戻り値を `Write-ExcelRange` にそのまま渡せるようにする。1 セルの `Value2` は配列で返らないので、1 セルも 1 行 1 列の形に直す。
- **エラー値は `@{ Error = '#DIV/0!' }` にする。** `Int32` のままでは、JSON にした時に数値と見分けられない。`Text` は表示の言語と列の幅で変わる。`'#DIV/0!'` という文字列にすると、同じ文字を書いたセルと見分けられない。
- **書き込みの大きさは `-Value` から決め、違う大きさの範囲は拒む。** Excel は大きさの違いを例外にせず、`#N/A` で埋めるか、はみ出た分を捨てる。ジャグ配列、`char`、配列の要素、`NaN`、長すぎる文字列も、例外にならずに値が変わるので、書く前に拒む。
- **文字列は、既定で文字のまま書く。** `001` が数値に、`1/2` が日付に黙って変わるのを防ぐ。全部の文字列に `'` を付けず、読み戻して変わったものだけに付けるのは、ほかのセルの `PrefixCharacter` を変えないため。ただし先頭が `=` か `＝` の文字列には、最初の代入から `'` を付ける。読み戻した時には、数式としてすでに計算されている。信頼できないデータの `=WEBSERVICE(...)` や外部参照が、その時点で動きうる。`'` を付けたセルに後から数値を書くと、`PrefixCharacter` は空に戻った（上の「文字列」）。
- **数式は `-Formula` を付けた時だけ、`Formula2` に書く。** `Formula` では、こぼれる数式に `@` が付いた。
- **`DateTime` の表示形式は変えない。** `Value` に書くと表示形式が付くが、helper が書式を変えると、ほかの書式を設定した後に呼んだ時に上書きする。
- **代入と読み出しは `InvokeMember` で行う。** helper は常に `object[,]` を代入するので、helper の中だけなら型は変わらない。それでも、利用者のスクリプトが先に `ConvertFrom-Json` の数値をプロパティの構文で代入すると、helper の中の配列の代入が落ちた（下の試験）。

`tests/Test-XlWright.ps1` の `range` が、これを確かめる（2026-11-17）。

- 型の混ざった 2 行 × 10 列、日本語、PSObject、`ConvertFrom-Json` の値を書いて読み戻した。`'` が付いたのは、Excel が変えた文字列のセルだけだった。
- `Set-ComProperty` を module の中で包んで、Excel に渡した配列を記録した。最初の代入で、`=1+1` と `＝1+1` には `'` が付いていた。`plain` と `001` には付いていなかった。書いた後のセルは、どれも数式でなかった。
- 先に `ConvertFrom-Json` の数値を `$sheet.Range('N1').Value2 = $json.n` で代入した後でも、書き込みは通った。
- 拒む入力（行の長さの違い、行が配列でない、範囲の大きさの違い、`char`、`Guid`、`NaN`、配列の要素、32768 字の文字列、シートの端、離れた範囲）は `ArgumentException` になり、範囲は変わらなかった。
- `Invoke-ExcelScript.ps1` から呼ぶと、エラー値は JSON で `{"Error":"#DIV/0!"}` になった。
- 次の写しは、どれも `range` で落ちた。`=` で始まる文字列に最初の代入で `'` を付けない写し、`'` を付けて書き直さない写し、`Formula2` の代わりに `Formula` に書く写し、エラー値を名前に直さない写し、行の長さを見ない写し、PSObject を外さない写し、1 セルを 1 行 1 列に直さない写し、シートの端を見ない写し、`char` を受け付ける写し、代入を `$Object.Value2 = $Value` にした写し。
- 代入を `$Object.Value2 = $Value` にした写しは、先に JSON の数値を代入する手順を試験に足す前は、合格した。代入を `$Object.$Name = $Value`（プロパティ名を変数にした形）にした写しも、その手順を足す前に合格した。足した後には流していない。

## 未確認

- `PowerShell` が COM のプロパティの代入を使い回す仕組み。PowerShell 7 での振る舞い。
- 表示の言語が日本語でない Excel、日付の書き方が違う地域の設定での文字列の解釈（`1/2` など）。
- `Currency`（`VT_CY`）の値。
- 結合したセルへの書き込みで、結合の範囲の一部だけを指定した場合。
- テーブル（`ListObject`）の中や、入力規則のあるセルへの書き込み。
- 1000000 行に近い範囲、16384 列に近い範囲での時間とメモリ。
- 2043、2050 のほかの、文書に無いエラー値。
