### アクセス拒否の読取り調査

ユーザーの指示により、T5の追加実験よりエージェント実行の原因調査を優先しています。
2026-10-29に次の結果を得ました。調査中にExcelの再生成や記録整理は行っていません。

| 確認対象 | 観測・根拠 | 限界 |
| --- | --- | --- |
| エージェントのシェルの整合性 | `whoami /groups /fo csv /nh`から、整合性SIDは`S-1-16-4096`（Low） | 失敗したdotnetプロセス自身のトークン全項目を直接採取したものではありません |
| 成功したユーザー側の整合性 | 同じコマンドの整合性SIDだけを抽出し、ユーザーから`S-1-16-8192`（Medium）の報告 | 個人SIDやアカウント名は収集していません |
| DCOMイベント | ユーザーのSystemログ照会で、19:44:51 JSTにExcelのCLSIDと一致するイベント10016が1件 | エージェントの同じ照会は`UnauthorizedAccessException`でした。イベント不存在とは扱いません |
| 拒否の種類 | ユーザーが抽出したparam1〜param5は「コンピューターの既定」「ローカル」「アクティブ化」、ExcelのCLSID、APPID「利用不可」 | 拒否対象アカウントを含む後半フィールドは収集していません |
| COM登録 | ExcelのCLSIDと`LocalServer32`が存在。照会したCLSIDのAppID値と実行ファイル名のAppIDキーはなし | 他の登録経路全体の不存在は証明していません |
| 機械既定のCOM記述子 | `HKLM\SOFTWARE\Microsoft\Ole`の`DefaultLaunchPermission`・`MachineLaunchRestriction`を読取り。両方ともSACLなし | 実効アクセス判定全体や、拒否した個別ACEの特定は未実施です |
| Codexの保存設定 | `~/.codex/config.toml`の該当設定は`windows.sandbox = "elevated"` | 保存値だけで、当該実行に使われたsandbox実装を確定しません |

失敗時刻・ExcelのCLSID・DCOMイベントの拒否種別が一致しています。
COM生成失敗と一致する、機械既定によるDCOMのローカルアクティブ化拒否を観測しました。
イベントの呼出し元と失敗したプロセスの直接対応、拒否原因の詳細は未確定です。
Low整合性の実行制約は有力な原因候補です。これだけが拒否原因であると分離して実証したわけではありません。
Microsoftの[COMと整合性の説明](https://learn.microsoft.com/en-us/windows/win32/com/the-com-elevation-moniker#cocreateinstance-and-integrity-levels)には、Low整合性クライアントの接続には既定の制限があると記載されています。
[Mandatory Integrity Control](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control)は、整合性による検査がDACLの検査とは別にあることを説明しています。
DCOMイベント10016の存在だけでは一般に動作失敗を証明しません。[Microsoftの説明](https://learn.microsoft.com/en-us/troubleshoot/windows-client/application-management/event-10016-logged-when-accessing-dcom)には無害な例もあります。今回は実際のCOM生成失敗との一致を根拠とします。

OpenAI公式の[Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox)では、sandboxは子プロセスにも権限制約を適用すると説明されています。
同資料の`elevated`はsandboxの実装名です。内部コマンドの管理者実行を意味しません。
このため、保存設定の名称を根拠に権限問題を除外しません。
