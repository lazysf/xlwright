# 0002: 継続利用するMCP接続基盤をR1で整備する

- Status: Accepted

2026-10-29に、製品へ育てるstdioサーバーと開発用登録をR1で整備する方針が承認されました。
シェルとアプリのMCP起動機構には整合性の差を観測しています。実測範囲は[結果記録](../notes/spike-0-results.md#mcp起動機構の権限診断)を参照してください。

## 比較と理由

接続実装をR3まで待つ案、開発専用の別サーバーを作る案、製品へ育てる接続基盤を前倒しする案を比較しました。
継続して同じ登録から検証するため、接続基盤を前倒しします。別サーバーから製品サーバーへの接続処理の作り直しを避けます。
通常のビルド・静的検証はシェルで行い、MCPを汎用コマンド実行機構にはしません。

## 境界

開発用機能は明示的な開発モードに分離します。既存T4コンソールの固定呼出しを使う検証は、製品の単一サーバー内STA構成の実証には数えません。
製品の通常起動に、リポジトリ探索・Spike・基準フィクスチャ・Codex同梱PowerShellを必須としません。CoreをMCPに依存させません。
所有記録、手動復旧、実機操作の承認条件は維持します。R2・R3の合格条件を前倒しで満たしたとは扱いません。

このリポジトリを製品の開発・検証・配布の正本とします。配布方式は実行依存と対象クライアントの確定後に選定します。
サーバーのインストール先と利用者のデータを分離し、更新・削除で利用者のブック・設定・所有記録を消す設計にはしません。
