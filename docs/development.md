2. 実機依存の仮説は[Spike-0](spike-0.md)で確認します。

6. 実装後の使い方と確認済みの制約を文書へ反映します。

検証コードを含め、依存パッケージは採用時にバージョンを固定します。

検証済みの処理は必要な部分をCoreへ移し、再現に必要な小さな実験は残します。一律の再実装は要求しません。
Excelの起動や設定変更を、通常の静的チェックに混ぜないでください。
実機検証には、使用するブックと変更・終了する対象を明示します。

## 初回コンソールの非COMチェック

リポジトリルートから実行します。このコマンドはExcelを起動しません。

```powershell
./spikes/Spike0/check.ps1
```

スクリプトはローカル設定でrestoreし、Debug・Releaseをビルドして、Releaseの`--self-check`を実行します。
パッケージ配布元は空です。子プロセスのCLIホーム・APPDATA・キャッシュは`.xlwright/spike0-build/`に限定します。
SDKの開発証明書生成を抑止します。呼出し元の環境変数を変更しません。
確認した結果と限界は[準備記録](notes/spike-0-preparation.md)を参照してください。
ビルド済みの自己チェックだけを実行する場合は、次を使います。

```powershell
dotnet spikes/Spike0/bin/Release/net10.0-windows/Spike0.dll --self-check
```

L2・L3の追加自己チェックは、合成した所有記録と終了安全確認の観測値を使います。
記録I/Oの各境界の失敗、部分書込み、読戻し不一致、管理外ブック等の拒否と後続処理の抑止が対象です。
実機の所有記録・ガード・復旧証拠は使用しません。Excelも起動しません。
証拠は`.xlwright/spike0-checks/<run-id>/`に保持します。
記録I/Oケースの`.failure.json`は失敗境界と状態、`.retained`はハンドル解放後の残存バイト列です。
終了拒否ケースの`.observation.json`は呼出し順と状態です。
チェック失敗時はこのディレクトリとコマンド出力を保持し、自動再送せず引き継ぎます。
合成ファイルの排他解放を、実Excelの終了や実機所有記録の完了とは扱いません。
追加コードのビルド・実行状況は[結果記録](notes/spike-0-results.md#l2l3の非com検証準備)を参照してください。

## 初回コンソールの実機実行

以下の正常系手順はユーザーによる実行の診断・保存ファイル・終了確認で検証しました。
直接のエージェントシェルではCOM生成のアクセス拒否を観測しました。T5では、手動復旧後のユーザー実行と、MCP経由の固定コンソール実行で次回開始まで確認しました。現在の実測範囲と再開条件は[実機結果](notes/spike-0-results.md#現在の状態と再開条件)を参照してください。未完了記録がある場合は、そのまま再実行しません。
対象と操作範囲の承認を得てから、対話可能なコンソールで実行します。

```powershell
dotnet spikes/Spike0/bin/Release/net10.0-windows/Spike0.dll --excel
```

操作範囲は次のとおりです。

1. `.xlwright/spike0/.xlwright.lock`を排他保持し、既存記録を検証します。未完了・不正・残存・同一性不一致なら生成せず拒否します。
2. `tests/fixtures/lifecycle.xlsx`を`.xlwright/spike0/runs/<run-id>/lifecycle.xlsx`へコピーします。基準ブック自体はExcelで開きません。
3. 起動印を確認してから専用Excelを生成し、Hwndから得たPID・生成時刻・プロセス名を確認します。既存ExcelのPIDなら操作を止めます。所有記録の確認後にコピーを開きます。
4. コピーの`Lifecycle!A2`を数値0から1へ変更し、読み戻して保存します。
5. 同一性、全ブックのパス、Protected View不在を確認します。保存しないClose後に再確認してQuitし、COM参照解放後に対象プロセスの終了を確認します。
6. 完了記録を確認して排他を解放します。保存ファイルのA2と基準ブックのハッシュを確認します。

既存ExcelへのCOM接続、プロセスの強制終了、設定の恒久変更は行いません。
開始・終了は各120秒、セル操作は30秒を上限とします。EOF等の終了要求も受理から120秒以内とし、保留呼出しの復帰待ちを含めます。無応答の呼出しを停止できる保証ではありません。
標準入力の`status`はCOMなしで状態を出力します。`stop`・EOF・Ctrl+Cは通常列を止める要求です。
入力を閉じるとEOFになるため、正常系の実行では入力を開いたままにします。
実行中のCOMが戻るまでは新しい後始末を投入しません。戻った後、時間切れでなく所有を確認できる場合だけ、保存せず安全確認付きの終了を試みます。

終了コード0はコピーの変更・保存・対象終了・記録完了・保存ファイル検査の成功です。
1は失敗または終了要求による中断、2は操作の期限切れによる結果不明です。
診断は実行ディレクトリの`diagnostics.jsonl`と標準出力へ出します。
ExcelのPID等の所有情報と失敗段階を確認します。セル内容を一般に収集するログではありません。

失敗・結果不明なら自動再送しません。記録を削除するだけで再実行しません。
起動途中の停止や失敗時は、イベント・警告等のインスタンス設定が復元されない可能性があります。
[手動復旧](architecture.md#初期の手動復旧)に従い、旧コンソールの終了を確認してから、人が対象Excelと未保存内容を確認します。
所有不明なら推測で終了しません。記録の整理や残存確認は、別途対象を示して行います。
実行後は対象プロセス・所有記録・診断、基準ブックのハッシュとGit差分を確認します。
観測は[Spike-0の記録方法](spike-0.md#結果の残し方)に従って残します。正常系だけでT5全体を完了にはしません。

## MCP起動機構の権限診断

`spikes/Spike0/InspectMcpLaunch.ps1`はPowerShell 7の一回限りの診断です。
Excel・MCP初期化・ツール呼出しは行いません。MCP接続失敗は想定内です。
`-ExperimentId`にGUID、`-Route`に`user-shell`・`agent-shell`・`mcp-launcher`を指定します。
同じスクリプトと実験識別子で3経路を比較します。
ユーザーのPATHに`pwsh`がない場合は、確認済みの既存PowerShell 7の絶対パスを使います。
Windows PowerShell 5への置換や実行ポリシーの迂回はしません。

記録は`.xlwright/mcp-launch-probe/<実験識別子>/<起動識別子>.json`に保存します。
整合性は標準`whoami.exe`の子プロセスから取得します。全グループは保存しません。
標準出力は空、標準エラーは起動識別子と測定成否だけです。
終了コード0は診断・保存の完了、1は失敗です。未知の結果をLow等に置き換えません。
`whoami`が10秒で終了しない場合は結果不明です。診断プロセスの終了だけで子プロセスの終了を確認したとは扱わず、人へ引き継ぎます。
記録にはプロセス同一性が含まれます。個人パスを含む登録用情報もGit管理外に置きます。

両シェルの測定成功後に、ユーザーがアプリの「設定 → プラグイン → MCP」へ専用名`xlwright-launch-probe`を一時登録します。
登録は確認済みPowerShell、`-NoLogo -NoProfile -NonInteractive -File`、診断スクリプトと引数、リポジトリ直下の作業ディレクトリを使います。
既存設定は変更しません。起動1回の後、アプリの標準エラーとJSONの識別子を照合します。
自動再起動がある場合は起動ごとの記録を残し、追加の手動再試行はしません。
測定後は専用登録を除去・再読込みし、記録されたプロセスの終了を確認します。
今回の画面では専用項目の「アンインストールする」で除去しました。登録時に記録が生成済みなら追加の起動は行いません。
登録拒否・追加権限要求・記録欠落・終了未確認なら停止します。
既存startingと基準ブックは変更しません。診断の成立をCOM生成やT5全体の合格とみなしません。
現在の結果は[実機結果](notes/spike-0-results.md#mcp起動機構の権限診断)を参照してください。

## 継続利用するMCP開発環境

[採用判断](adr/0002-development-mcp-foundation.md)に基づくstdio接続基盤です。
引数なしでは開発用ツールを公開せず、リポジトリ探索やExcel操作を行いません。製品のExcel操作APIは未実装です。
`--development`で起動すると、下記の6ツールだけを公開します。作業ディレクトリはリポジトリ直下、起動は確認済み`dotnet.exe`とビルド済みDLLを使います。
アプリからの接続・更新・再接続と実Excelの成立性は、ローカルの非COM検証とは別に確認します。

| ツール | 入力と結果 |
| --- | --- |
| `dev_status` | 入力なし。起動識別子、サーバーとSpike DLLのSHA-256、受付識別子、状態、終了コード、直近の観測、相対ログ先 |
| `dev_excel_smoke_start` | 入力なし。既存Spike0の固定`--excel`を1回開始し、受付識別子を含む状態を返す。実行範囲の事前承認が必要 |
| `dev_excel_end_refusal_start` | 入力なし。固定L3ケースを1回開始する。主コピーと管理外コピーを同じ専用Excelで開き、終了拒否を観測する。事前承認が必要 |
| `dev_excel_record_fault_starting_start` | 入力なし。固定L2ケースSを1回開始する。startingの書込み前に失敗を注入し、Excelを生成しないことを観測する。事前承認が必要 |
| `dev_excel_record_fault_completed_start` | 入力なし。固定L2ケースCを1回開始する。主コピーの保存と専用Excelの終了確認後、completedの書込み前に失敗を注入する。事前承認が必要 |
| `dev_excel_smoke_status` | `receiptId`（GUID）。そのサーバーが受け付けた実行の状態を返す |

開発用状態は`idle`・`running`・`completed`・`failed`・`unknown`です。製品のセッション状態とは異なります。
`manualReviewRequired`は開発アダプターの状態とガードに関する値です。falseでも、所有記録の復旧完了や実Excel操作の承認を意味しません。
応答の`scenario`は未受付時null、受付後は`smoke`・`end-refusal`・`record-fault-starting`・`record-fault-completed`のいずれかです。状態照会は全ケースの受付IDを受け付けます。
`completed`には、正常系（`smoke`）の子プロセスの終了コード0と最後の`saved-file.verified`が必要です。MCPの受付成功は実験成功ではありません。
開始応答を失ったら`dev_status`を呼び、開始を再送しません。並行開始、失敗・結果不明後の開始は拒否します。
Spike DLLが起動時のハッシュから変わった場合は、停止・再接続を要求します。

### ビルドと非COM検証

既存Spikeのビルドを先に行います。`pwsh`がPATHにない場合は確認済みPowerShell 7の実行ファイルから起動してください。Windows PowerShell 5への置換はしません。

```powershell
./spikes/Spike0/check.ps1
./src/XlWright.McpServer/check.ps1 -Restore
```

初回の`-Restore`は、公式NuGetだけを指定した設定とlock fileで依存を復元します。依存取得の利用条件は[環境記録](notes/verification-environment.md#mcp接続基盤の依存確認)を参照してください。
SDKの初回処理とキャッシュは`.xlwright/mcp-build/`に限定します。通常の再ビルドは`-Restore`を省略し、ネットワーク復元を行いません。
チェックはDebug・Releaseをビルドし、合成記録とテスト用プロセスで接続・拒否・出力・終了を検証します。実Excelは起動しません。

### 登録と更新

このリポジトリを信頼済みプロジェクトとして開き、プロジェクトの`.codex/config.toml`で専用名`xlwright-dev`を設定します。
Codexの[プロジェクト単位MCP設定](https://learn.chatgpt.com/docs/extend/mcp)を使用します。設定画面への手入力は不要です。
初回ビルド・非COMチェック後に、一度だけ次を実行します。実行場所に依存せず、スクリプトのあるリポジトリを対象にします。

```powershell
./src/XlWright.McpServer/setup-development.ps1
```

スクリプトは`dotnet.exe`とビルド済みDLL・リポジトリの絶対パスを解決し、[テンプレート](../src/XlWright.McpServer/codex-config.toml.template)から生成します。
作成対象はこのリポジトリの`.codex/config.toml`だけです。ビルド・依存復元・MCP起動・ホーム設定の変更は行いません。
生成設定には`mcp_servers.xlwright-dev`の`command`・`args`・`cwd`だけを含めます。権限・sandbox・trustの設定は含めません。
既存の`.codex/config.toml`があれば、読み取ったり書き換えたりせず停止します。他の設定との統合は内容と操作範囲を別途確認します。
reparse pointのある対象パスでは停止します。保護された設定への書込みが拒否された場合、別の場所へ設定を置いて回避しません。
実機パスを含む生成設定はGit管理外です。Gitにはスクリプトとテンプレートを残します。

Claude Codeでは、Git管理する[.mcp.json](../.mcp.json)で同じ専用名を設定します。Claude Codeの[プロジェクト単位MCP設定](https://code.claude.com/docs/en/mcp)を使用し、生成手順はありません。
設定は`mcpServers.xlwright-dev`の`type`・`command`・`args`だけです。`command`は.NETの標準インストール先の`dotnet.exe`です。別の場所に.NETがある環境では動きません。
サーバーDLLは公式文書の例に従い`${CLAUDE_PROJECT_DIR:-.}`からの相対パスで指定します。変数が未設定なら起動時の作業ディレクトリからの相対パスになります。
Claude Codeの公式文書には作業ディレクトリの指定項目と既定値の記載がありません。サーバーは作業ディレクトリに`spikes/Spike0/Spike0.csproj`がなければ開始を拒否します。接続後は`dev_status`の起動識別子と、このリポジトリの`server.json`を照合して作業ディレクトリを確認します。
プロジェクト単位の設定は既定では対話セッションでの利用前にユーザーの承認を求めますが、これを安全の層には数えません。承認すると、Excelを操作する固定の開発ツールが使えるようになります。接続先はビルドハッシュの照合で確認します。
CodexとClaude Codeの両方を開いている場合は、それぞれが別のサーバーを起動します。開始の競合は共有のガードで拒否されますが、更新時は両方の旧サーバーの終了を確認します。

生成後、ユーザーがプロジェクトを開き直し、設定の読込みを確認します。信頼されていないプロジェクトでは読み込まれません。
このアプリの版での再読込み・ツール反映は実測で確認します。ファイル生成だけで接続成功とは扱いません。
以前のGUI用`.xlwright/mcp-development/registration.txt`は使用しません。GUI登録を既に作っている場合は重複の有無を確認し、ユーザーがその専用項目を整理してから接続します。
プロジェクトの移動等で再生成が必要な場合も既存設定を自動削除しません。対象を確認して人が判断します。
起動だけではExcelを生成しません。`dev_status`の起動識別子・ビルドハッシュを、ローカルの`server.json`と照合します。
更新は、実験が動いていないことを確認し、ユーザーが専用項目を停止して旧サーバープロセスの終了を確認してから行います。
ビルド・チェック後にユーザーが再接続し、新しい起動識別子とビルドハッシュを確認します。接続中のDLLを上書きして更新完了とは扱いません。
今回は、ユーザーがアプリを通常終了した後に通常PowerShellでチェックを実行し、アプリを起動し直す手順を使いました。戻った後に旧サーバー不在と新サーバーの同一性を照合しました。再読込みやアプリ終了だけで旧プロセスが消えるとは仮定しません。

### 実Excelと失敗時の引継ぎ

開始前に対象と変更・終了の範囲を提示し、承認を得ます。対象は上記の[初回コンソール](#初回コンソールの実機実行)と同じ新規コピーです。
未完了の所有記録がある場合は、証拠保全と手動復旧の承認を必要とします。開始ツールは所有記録を整理しません。
既存の`.xlwright/spike0/`を継続使用し、別の作業領域で拒否を回避しません。

開発ログは`.xlwright/mcp-development/<起動識別子>/`へ保存します。`server.json`、受付識別子付きのプロセス同一性、標準出力・標準エラー、結果が含まれます。
ログ全文には実機パス等が含まれます。Git管理外で保管し、文書へそのまま転記しません。
`.xlwright/mcp-development/active-smoke.json`は実行中・未確認実験のガードです。新規作成で競合を拒否し、成功結果の保存後だけ削除します。
失敗・結果不明・結果保存失敗では保持します。ガードが残った場合、再起動だけでは再実行できません。所有記録と同様に、根拠と対象を示した手動判断へ引き継ぎます。

通常の操作期限はSpikeの契約を維持します。アダプター全体の観測上限は360秒です。超過や出力読取り失敗では結果不明として入力を閉じます。
MCPのEOF・終了時にも子の入力を閉じ、最大125秒待ちます。終了未確認ならガード・診断を保持し、プロセスを強制終了しません。
この待機はCOM停止を保証しません。所有不明のExcelへ接続・終了せず、失敗後に自動再送しません。

### L3固定ケースと手動引継ぎ

`dev_excel_end_refusal_start`はSpike0の固定`--excel-end-refusal`だけを呼びます。
主コピーのA2を1に変更し、別の管理外コピーを同じ専用Excelで開いてから、主コピーを保存して通常終了を試みます。
このケースだけ専用Excelを表示し、Captionに実行識別子を示します。基準ブックを直接開きません。
拒否後はCOMを照会せず、保持情報・OS照会・保持ハンドルからの読取りで証拠を記録します。
`end-refusal.verified`は子コンソール終了前の状態・所有記録・排他・プロセス生存を確認した診断です。
期待する拒否でも終了コード1、アダプターはfailedでガードを保持します。completedへの整理を意味しません。
コンソールの最終イベントはrun.failedです。期待との一致はログ内のend-refusal.verifiedと終了コード・保持記録を照合し、latestObservationだけで判定しません。
証拠不足・診断失敗では当該イベントを成功の根拠にしません。再送せず手動確認へ渡します。

手動復旧前に対象・記録ハッシュ・未保存内容と整理範囲を提示して承認を得ます。
旧MCPと子コンソールの終了確認後に、人が対象Excelを確認して保存・破棄と終了を判断します。
対象Excelの終了後に証拠を保全し、個別承認した範囲で所有記録を排他保持してcompletedへ更新し、flushと読戻しを確認します。
ガードは保全・終了確認・個別承認後だけ除去します。確認不能なら両記録を保持して復旧を保留します。
復旧手順が途中で止まった場合は、既に終えた操作と記録の現在値を照合してから再開します。
対象Excelを既に閉じた場合、元のプロセスを再現するために開き直しません。終了済みの確認と、再接続後のMCPを含む終了確認へ手順を合わせます。
アプリの停止・更新・再接続は既存の登録を継続し、確認済みのアプリ通常終了手順を使います。

### L2固定ケースと手動引継ぎ

2つの開始ツールは、Spike0の固定`--excel-record-fault-starting`・`--excel-record-fault-completed`だけを呼びます。
既存記録の確認後に、通常経路と同じ記録I/Oの`write`直前へ1回の失敗を注入します。対象の種別以外の書込みと読取りには注入しません。
実ストレージの障害や電源断を起こすものではありません。ACL・属性・作業領域の変更で失敗を作りません。

ケースSはstartingの書込み失敗です。Excelを生成せずclosedとなり、記録は実行前のcompletedのままです。主コピーは開きません。
Spike0は排他をプロセス終了時に解放します。ケースSの`record-fault.verified`は終了前の保持を記録するもので、解放は子コンソールの終了後にロックファイルを排他で開けることで確認します。
ケースCは通常の保存・Close・Quit・対象プロセスの終了確認の後、completedの書込み失敗です。isolatedとなり、記録はownedのまま保持します。
失敗後はCOMを照会せず、保持情報・OS照会・保持ハンドルからの読取り・Excelなしの保存ファイル検査で`record-fault.verified`を記録します。
ケースSでは開始時に記録したEXCEL以外のプロセスが現れていないことも確認します。新しいプロセスがあれば証拠不足とし、終了対象には選びません。
期待どおりでも終了コード1、最終イベントはrun.failed、アダプターはfailedでガードを保持します。期待との一致はログ内の`record-fault.verified`と終了コード・保持記録で判定します。
各ケースの後はアダプターがfailedでガードも残るため、再接続と後始末が済むまで次の開始を拒否します。ケースSで期待と異なればケースCへ進みません。

ケースSの後始末は、子コンソールの終了と排他の解放を確認した後の証拠保全と、対象・ハッシュを示した個別承認後のガード除去だけです。所有記録は変更しません。
ケースCの後始末は[L3固定ケース](#l3固定ケースと手動引継ぎ)と同じ順で、旧MCPと子コンソール・対象Excelの終了を確認してから所有記録をcompletedへ更新し、ガードを除去します。Excelは既に終了しているため、開き直しません。
ケースCの後に残るownedのPIDは既に不在です。後始末の前にSpike0を直接起動すると、次回開始の規則で記録がcompletedへ更新されるため、直接起動しません。
