# Spike-0 の実施計画

## 目的と現在の状態

Excel COM・VBE・MCPクライアントの実機依存の挙動を確認し、各PoCへ進むための設計入力を得ます。
検証対象の設計は [architecture.md](architecture.md)、操作契約は [api.md](api.md) に定義しています。

現在は計画のみです。
検証コード、実機実験、結果記録はまだありません。
本書の作成を、実機検証の実施や仮説の成立とみなさないでください。

## 実施順序と着手条件

すべての検証項目を一括した待ち条件にはせず、次の実装で必要になる検証と契約を先に確定します。
未実施の項目は記録に残し、その仮説に依存する実装へ進みません。

| 段階 | 作業 | 次へ進む条件 |
| --- | --- | --- |
| 準備 | 検証環境、依存の版、所有確認・通常終了・診断の最小の検証コード | 下記の故障注入前の確認に合格 |
| 基盤のSpike | S1〜S4・S9・S10の起動設定・S11〜S14 | セル、計算、STA、開始・終了、残存Excelの扱いを評価可能 |
| PoC-1 | 6操作による最小の縦断と異常系 | 本書のPoC-1合格条件を満たす |
| VBAのSpike | S5・S6・S7・S15 | 反映方式とラッパー経由の実行契約を確定 |
| PoC-2 | ソース反映、実行ラッパー、非同期マクロ、基本ダイアログ応答 | 下記のPoC-2着手条件と対象機能の検証を満たす |
| 残りのP0-core | 初回抽出、クラス・ドキュメント、テストコピー、内部テスト等 | 要件の完了条件を満たす |

S10の `ForceDisable` でのVBA抽出は、`project_init` の実装前までに確認します。
S11・S12の停止実験には最小の既知のVBAフィクスチャを使います。
その準備を、VBA反映機能やマクロAPIの実装完了とは扱いません。
S13はstdioの終了を観測する最小サーバーから始め、完成したMCPサーバーを待ちません。

S14では、手動計算で保存したブックを開き、参照元セルの変更後に取得する値を確認します。
マクロが計算モードを変えた場合も確認します。
測定前に計算モードを一律に変更する実装へ固定せず、既存操作が保証する結果の鮮度と必要な計算処理を決めます。

S15では、0・1・複数引数、数値・日本語文字列・真偽値・空値、戻り値、捕捉可能エラー、JSONの引用符と改行を確認します。
管理対象外のテスト用ブックに同名マクロを置いても、指定した主ブックだけが実行されることを確認します。
ラッパーの起動先と、ラッパーが呼ぶ対象マクロの両方を検査します。

## 着手前の確認

- 各実験の対象項目、期待する観測、失敗時の終了方法を先に決めます。
- [開発ガイド](development.md#配置方針)の位置へ、.NET 10・STA・Office Interopによる検証コードを作成します。依存の採用と版の確定は、その作業で行います。
- SDK・Excelの版とビット数、必要なVBIDEアクセス設定の状態を確認します。組織の設定を変更して回避しません。
- 専用Excelと使い捨てブックを用意します。業務ブックや個人ファイルを実験対象にしません。
- 所有確認と終了安全確認を満たす手順を用意します。無限ループやモーダル表示を試す前に、人に確認を求める経路も決めます。
- ブック外への副作用がある実験は、その対象と影響を明示します。同一ユーザーによる実行は、OSによる隔離ではありません。

## 故障注入前の確認

S7・S11・S12でモーダル表示・無限ループ・強制終了を試す前に、次を実測します。

1. 専用Excelの起動から、PID・生成時刻・プロセス名による同一性確認まで成立します。
2. 使い捨てブックの操作と通常終了が成立し、対象プロセスの終了を確認できます。
3. 管理対象外のテスト用ブックが同じインスタンスにある場合は、自動終了を拒否します。
4. 所有記録の読取り・更新失敗を成功扱いせず、追跡に必要な情報を失わないことを確認します。
5. [承認待ちの安全条件](architecture.md#承認待ちの安全条件)を確定し、当該条件の検査と、人に確認を求める経路を用意します。

この確認に失敗した場合は、故障注入へ進みません。
Protected Viewを含む終了確認の具体的なケースは、安全条件を承認した後に確定します。

## 結果の残し方

実施後の記録は `docs/notes/spike-0-results.md` に作成します。
結果が出る前に、成功例を埋めた記録は作りません。

項目ごとに、次を残してください。

- 項目ID、実施日、SDK・Excelの版とビット数。
- 検証コードのリポジトリ内パスと、再現コマンド・前提条件。
- 期待した挙動と実際の観測。例外や時間は、確認した範囲で記録します。
- 判定（仮説を支持・仮説と不一致・結果不明・未実施）。未実施の項目を合格に含めません。
- 設計への影響と、追加確認が必要な点。
- 後始末の結果。所有Excelの残存と、Git差分の有無を含めます。

ログに含まれる個人のパスや識別情報は、記録へ転記しません。
レビュー済みの結果を根拠に、仮説と不一致だった仕様とPoC-1への影響を整理します。
設計変更が必要なら根拠と影響を示して承認を得た後、対応する正式文書を更新します。

## PoC-1の範囲と合格条件

対象はMCP → 専用STA → 専用Excelの経路と、`session_start`・`session_status`・`range_get`・`range_set`・`session_save`・`session_end` です。
セル操作は単一セルから始め、P0-coreで矩形へ拡張します。

1. MCPから実Excelのセル値を読み書きできます。
2. 専用Excelを識別でき、通常利用のExcelに干渉しません。専用Excelは既定で非表示です。
3. 指定した実ブックだけが直接更新されます。
4. 保存・終了・別セッションでの再取得が成立します。
5. 同じプロジェクトへの2つ目のサーバーの開始を `CONFLICT` で拒否します。
6. 明確な保存失敗を成功と報告せず、`ready` とロックを維持します。
7. 強制終了・COMタイムアウトで `isolated` へ移り、STA停止中も状態照会が応答します。人の承認後の `force` による所有Excel終了後、保留中呼出しを既定時間内に回収して再開できます。`STA_UNRECOVERABLE` が試験中に発生しません。
8. サーバー終了時と次回開始時の後始末は、終了安全確認を満たすExcelだけに行います。管理外ブックがある場合と無応答時は `EXCEL_NEEDS_REVIEW` とし、通常終了でも同じ条件を適用します。
9. 所有記録の破損は `SESSION_RECORD_INVALID` で拒否し、`force` でも突破できません。通常利用の別Excelを `force` でも終了しません。

ライフサイクルの契約を確定する際は、[計画レビューの確認事項](notes/plan-review.md#未確認の失敗経路)にある、起動と所有記録の間の停止、タイムアウト後の遅延完了も検証ケースへ落とします。
テストコピーを開いている途中の停止は、テスト実行機能の実装時に検証します。
いずれも、発生時の期待動作を先に確定してから実験します。

不成立時は[設計の撤退条件](architecture.md#終了と残存excelの後始末)を評価します。
まず最小再現で、実装不良・環境条件・構成上の制約を区別します。
実装不良なら修正して該当条件を再検証し、構成上の制約が残る場合は代替構成を比較します。
原因不明や合格条件の未達を、継続実装の承認とは扱いません。

## PoC-2へ進む前の確認

- S5・S6・S7・S15の結果と設計への影響が記録されています。
- VBA反映・マクロ実行・状態照会・基本ダイアログ応答の入出力スキーマを確定しています。
- `xw_Runtime` の結果JSON、対応する引数と戻り値、ラッパー経由の有効引数上限を確定しています。
- 部分反映の失敗、ラッパーで捕捉したエラー、結果不明による隔離を区別する検証ケースがあります。

PoC-2ではVBA反映、実行前の自動反映、`xw_Runtime`、非同期マクロ、タイムアウト、基本ダイアログ応答を検証します。
機能ごとの検査に加え、次の一連の反復を合格条件とします。

1. AIエージェントが標準モジュール1本のソースを作成します。
2. MCP経由の実行要求でソースを自動反映し、引数付きマクロを実行します。
3. 実行状態を照会し、戻り値と変更されたセルの値を期待値と比較します。
4. 同じソースを修正し、同一セッションで再実行して結果の変化を確認します。
5. 保存・終了・再接続後にも反映と実行が成立することを確認します。
6. 基本ダイアログの事前応答と、明確なVBA実行時エラーからの修正・再実行を確認します。

最初の1回の成功だけでは、開発・修正の反復が成立したとは判定しません。
その後、残りのP0-coreを実装し、[要件の完了条件](requirements.md#p0-coreの完了条件)を確認します。
