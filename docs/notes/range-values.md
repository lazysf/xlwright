# 範囲の値と数式の読み書き

`range_read`と`range_write`（[API](../api.md#range_read段階1)）が依存する、遅延バインドの`Value2`・`Formula`・`ClearContents`の振る舞いの記録です。
確かめた日は2026-11-03です。

## 版

- Windows 11 Pro 10.0.26300、.NET 10.0.14（x64）
- Microsoft 365 Excel 64-bit 16.0.20527.20112
- 起動した場所: Claude Codeのデスクトップアプリの会話のシェル（Git Bash）から起動した`dotnet`

## 再現の手順

```powershell
dotnet run --project spikes\range-values
```

実験は、STAのスレッドから専用のExcelを1つ起動し、所有を確かめます（新しいPID、`EXCEL.EXE`、起動を求めた後の生成）。確かめられなければ、触らずに止まります。
ファイルの無い新しいブックで試し、保存せずに閉じます。

## 判定

### 読んだ値の型

支持。遅延バインドの`Value2`は、数値を`Double`、文字列を`String`、真偽値を`Boolean`、空を`null`で返した。
複数のセルでは、下限が1の`object[,]`を返した。1つのセル（`A1`と`A1:A1`）では、配列ではなく値を返した。
日付と通貨の表示形式のセルも、`Value2`は`Double`を返した。

### セルのエラー

支持。セルのエラーは、`Int32`のHRESULT（`0x800A0000`にエラーの番号を足した値）で返った。

| 数式 | `Value2` | 番号 |
| --- | --- | --- |
| `=1/0` | -2146826281 | 2007（`#DIV/0!`） |
| `=NA()` | -2146826246 | 2042（`#N/A`） |
| `=SQRT(-1)` | -2146826252 | 2036（`#NUM!`） |
| `=NOSUCHFUNC()` | -2146826259 | 2029（`#NAME?`） |
| `="a"+1` | -2146826273 | 2015（`#VALUE!`） |
| `=A1 B1` | -2146826288 | 2000（`#NULL!`） |
| `=#REF!` | -2146826265 | 2023（`#REF!`） |
| `=LAMBDA(x,x)` | -2146826238 | 2050（`#CALC!`） |

同じ値の数値を入れたセルは、`Double`で返った。そのため、`Int32`かどうかでエラーを見分けられる。
`#SPILL!`は出せなかった（次の節）。

### 数式

支持。`Formula`は、数式のセルで数式を、定数のセルで値の文字列を、空のセルで`""`を返した。
`Formula`に文字列の配列を書くと、`=`で始まる要素は数式に、ほかは定数になった。`""`の要素は空になった。
ドイツ語の関数名（`=SUMME(1,2)`）は`#NAME?`になった。`Formula`は英語の関数名で解釈する。
`Formula`で書いた`=SEQUENCE(2)`は、spillしなかった。下のセルは空のままで、`Formula`は`=SEQUENCE(2)`を返した。

### 書く値の解釈

支持。`Value2`に書いた文字列は、人の入力と同じに解釈された。`"1/2"`は日付のシリアル値に、`"001"`は1に、`"2026-11-03"`は日付に、`"TRUE"`は真偽値になった。`"'x"`は文字列`x`になった。
`"=1+1"`は数式になった。
`null`の要素は、値のあったセルを空にした。
2^53を超える`long`は、精度を失った（9007199254740993が9007199254740992になった）。

### 書込みの失敗

- `Formula`に不正な数式（`=SUM(`）を1つのセルで書くと、`COMException`（`0x800A03EC`）になった。
- 不正な数式を含む配列を`Formula`に書くと、`OutOfMemoryException`（`0x8007000E`）になった。前の要素は書かれ、後の要素は書かれなかった。
- 範囲より大きな配列は、黙って切り詰められた。小さな配列では、余ったセルが`#N/A`になった。どちらも例外にならなかった。
- 保護したシートへの`Value2`・`Formula`・`ClearContents`は、`COMException`（`0x800A03EC`）になった。読むことはできた。
- 結合したセルの一部への`ClearContents`は、`COMException`（`0x800A03EC`）になった。一部への`Value2`は、例外にならなかった。

### 範囲とシートの指定

- `Range`は、小文字、`$`、逆順（`B2:A1`）、複数の範囲（`A1,B2`）、列（`A:A`）、行（`1:1`）を受け付けた。列は1,048,576セル、行は16,384セルだった。
- 範囲の外（`XFE1`・`A0`・`A1048577`）、ほかのシートの修飾（`Sheet2!A1`）、無い名前は、`COMException`（`0x800A03EC`）になった。
- 無いシートの`Worksheets.Item`は、`DISP_E_BADINDEX`（`0x8002000B`）になった。シートの名前は、大文字と小文字を区別しなかった。

### 再計算

支持。手動の計算で値を変えた後、`CalculationState`は`xlPending`（2）だった。`Calculate`の後は`xlDone`（0）で、計算を終えた値を読めた。

### 速さ

10,000セル（100×100）を`Value2`で書くと79 ms、読むと5 msだった。シート全体の`ClearContents`は6 msだった。1回の測定です。

## 後始末とGit差分

- 実行の前と後で、EXCELのプロセスは0だった。
- 実験は中間のCOMのオブジェクトを解放していないため、`Quit`の後75秒で終わらず、所有を確かめたプロセスを終了させた。製品のCoreは中間のオブジェクトも解放する（[記録](sta-com.md)）。
- Gitで管理するブックには触れていない。ファイルは作っていない。
- Gitの差分は、実験の追加と本書の追加だけです。
