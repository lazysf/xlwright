# 0010: 標準・クラスモジュールを毎回すべて置き換える

- Status: Accepted

2026-11-02にユーザーが承認しました。
VBAの反映では、ブック内の標準・クラスモジュールをすべて削除してから、アプリのVBAソースのファイルをすべて取り込みます。
ソースに無いモジュールはブックから消えます。シートとブックのモジュール（ドキュメントモジュール）は対象外で、削除せずにコードを更新します。

## 背景

ユーザーは、これまでのAIエージェントを使った開発で、自作のマクロをこの方式で使ってきました。
マクロは、ブックのプロパティに設定した相対パスから標準・クラスモジュールを取り込み、取り込む前に既存の標準・クラスモジュールをすべて削除していました。
文字コードと改行の変換、BOMと`Attribute`行の扱いにも対応していました。

## 検討した代替案

モジュール単位の反映を比較しました。ソースのハッシュで変わったモジュールを判定し、一時改名 → Import → 旧モジュールのRemoveで置き換える案です。
ソースが無いだけではモジュールを削除せず、削除は明示の操作で行います。
実績がなく、差分判定と改名の手順を外部のCOMから確かめる必要がありました。

## 影響

ブックの中にしか無いモジュールは、次の反映で消えます。既存のブックからソースを取り出してから使う前提です。
モジュールを消すための操作は設けません。ソースのファイルを消せば、次の反映で消えます。
反映の途中で失敗すると、ブック内のモジュールが欠けた状態になります。保存はしません。
