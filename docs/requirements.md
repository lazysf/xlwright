# 要件

## 目的

xlwrightは、AIエージェントがExcel業務アプリケーションの開発・実行・検証を反復するための基盤です。
従来、人が行っていたVBAソースの取り込み、マクロ実行、結果の取得を自動化します。
対象はAIエージェントそのものの開発ではありません。

人間は仕様の決定、重要な設計変更、成果物の最終承認を担当します。
AIエージェントは合意済みの仕様と許可範囲内で、実装、実行、検証、修正を反復します。
全判断の無人化は目標にしません。

## 利用環境と提供形態

- AIエージェントとWindows版Excelは、同じWindows端末・同じユーザーで動かします。
- 初期の検証対象はWindows 11 x64、.NET 10、Microsoft 365 Excel 64-bitのデスクトップ版です。他の環境は未検証です。
- CodexとClaude Codeから共通に利用する、ローカルstdioのMCPサーバーを提供します。
- P0は1プロジェクトにつき1主ブック・1編集セッションです。同じプロジェクトへのMCP経由の同時編集を禁止します。
- ユーザーの日常業務用Excelと、xlwright専用Excelが同時に動く前提です。

これらは設計上の対象です。現在の実装・検証状況は [README](../README.md#現在の状態) を参照してください。

## 初期実用版の範囲

初期実用版はP0-coreの完成をもって成立します。
その前の到達点として、合成した小さなブックと業務用の標準モジュール1個で開発反復を確認します。
必要な内部支援モジュールは別に扱います。
機能数や復旧の自動化自体を目標にせず、通常の反復に必要な人の定型操作を減らします。
初期の異常時は、後続操作を止め、人が確認・後始末してサーバーを再起動できればよいものとします。
これはP0-coreの機能範囲の削除ではありません。段階ごとの範囲は [ロードマップ](../ROADMAP.md) に従います。

| 領域 | P0-core |
| --- | --- |
| ブック | 新規作成、既存ブック取り込み、保存、終了、状態取得、読取専用の検出 |
| セル・シート | 値・数式の読み書きと消去、計算結果と結合状態の取得、シートの作成・削除・改名・一覧 |
| VBA | 標準・クラスモジュールの追加・更新・明示削除、既存ドキュメントモジュールのコード更新、初回取り込み時の抽出 |
| 実行 | 実行前のソース反映、非同期マクロ、実行状態と結果の取得 |
| ダイアログ | VBAラッパーによるメッセージ・入力・ファイル選択・フォルダー選択・保存先指定・キャンセルへの事前応答 |
| テスト・診断 | VBA内部テストの検出と実行、アサーション、実行ごとのブックコピー、構造化エラー、診断ログ、タイムアウトと後始末 |
| エージェント連携 | 持続的セッション、明示的な対象指定、同時操作の拒否、引き継ぎ時の終了・開始 |

VBAソースはファイルを正本とし、実ブックへ一方向に反映します。
シート・数式・書式はGitワーキングツリー内の実ブックを正本として直接編集します。
テスト時だけ実行ごとの使い捨てコピーを使います。

## 後続の範囲

ActiveXコントロールは非対応とします。作成・編集・実行の動作保証は提供しません。
これは非対応方針であり、ActiveXの自動検出・実行防止を保証するものではありません。

P0-extは、P0-coreの運用後に人間が着手を判断します。
対象は書式、行列操作、結合・解除、シート複製・移動、条件付き書式、入力規則、並べ替え、オートフィルター、名前定義、保存済みブックの基本差分、成果物出力です。
詳細なAPI契約は着手時に定義します。

Table、Power Query、UserForm、VBA参照設定、汎用UI Automation、印刷、グラフ、ピボットテーブル、図形、複数ブックや並列実行は後続検討です。
将来の必須実装を約束するものではありません。

初期必須成果物に、一般利用者向けGUI、独立CLI、公開SDK、リモート接続は含めません。
独自バックアップ、自動スナップショット、OOXMLを正本としたブックビルド、Git操作の代行はP0に含めません。

## 安全性と結果の要件

- 結果不明と明確な失敗を区別します。結果不明の要求を自動再送しません。
- 部分的に変更された操作を成功として報告しません。原子性や自動ロールバックは保証しません。
- 所有が確認できないExcelを終了しません。専用Excelに混入したユーザーの未保存作業も終了安全確認の対象とします。
- 専用Excelとテストコピーは、同じユーザー権限で動くVBAの副作用を隔離しません。
- 組織のセキュリティ設定やVBAプロジェクトの保護を迂回しません。
- セル値やVBA全文を無条件にログへ出しません。

具体的な制御と限界は [architecture.md](architecture.md) に定義します。

## P0-coreの完了条件

実Excel上で、AIエージェントがMCP経由で次の反復を行えることを確認します。

1. 標準・クラス・ドキュメントモジュールのVBAソースを反映します。
2. マクロとVBA内部テストを実行し、事前指定したダイアログ応答を返します。
3. 値・数式・実行結果を取得して検証します。
4. 保存・終了・再開を行います。
5. 異常時は結果不明を明示し、安全条件に従って後始末します。

通常の反復から定型的な人手操作を除くことが目標です。
仕様判断、最終承認、終了安全確認が成立しない場合の人の判断は残ります。
