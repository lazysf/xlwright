## 比較表の読み方

表の「開始中」「終了中」は内部遷移です。新しい公開状態ではありません。
推奨案では、その間の状態照会は開始元の `closed`、終了元の `ready` または `isolated` と `busy: true` を返します。
応答の具体的な形はT2の判断対象です。
`isolated` への移行後は、通常の編集・保存・開始を拒否します。

所有記録は次の意味で区別します。これは形式やフィールド名の提案ではありません。

- **未開始**: ロックファイルが存在しない初回、または終了確認後に明示的に記録をクリアできた状態。
- **起動未完了**: Excelを生成する前に残す印。所有プロセスの情報はまだ確定していません。
- **所有確定**: PID・生成時刻・プロセス名・確定した主ブックのパスを検証できる記録。以後、対象Excelが残る間は別の起動の情報に置き換えません。
- **不正・読取不能**: 必須情報の欠落、途中書込み、未知の形式、読取り失敗等。正常終了した記録とはみなしません。

「クリア」は終了確認済みであることを記録へ反映する論理操作です。
空ファイル、ファイル削除、明示的な完了記録のどれで表すかは未承認です。
推奨は明示的な完了記録です。新規作成直後の空ファイルと正常終了を区別できるためです。
既存の空・不正ファイルを初回起動とみなす移行規則は設けません。

エラー名のうち `SESSION_RECORD_INVALID`・`EXCEL_NEEDS_REVIEW`・`STA_UNRECOVERABLE` は現行文書の診断名です。
共通エラーコード6種類との対応や、新たな記録I/O失敗の `detail` はT2で決めます。
本書では未定義のコードを新設しません。
次回開始の残存処理でも、終了操作や照会が未回収なら `isolated` とロックを維持します。
単に開始を拒否しただけで、保留処理のあるサーバーを再利用可能な `closed` にはしません。

## 所有記録を更新する境界

推奨は、既存の単一ロックファイルを維持し、更新回数を必要な境界に限る案です。
通常の `ready`・`busy`・`isolated` の変化は所有記録へ書き込みません。
これにより、対象が生きている間に完成済みの所有情報を繰り返し上書きする必要を減らせます。

1. 既存ファイルを開くときは、検査前に作り直し・切詰めをしません。排他を確保してから既存記録を読みます。
2. 既存の所有記録を解決した後、Excel生成より先に起動未完了の印を書きます。
3. Excelの同一性を得た直後に所有記録を完成させます。完成の確認前に主ブックを開きません。
4. 保存失敗、タイムアウト、安全確認拒否、サーバー停止要求だけでは記録をクリアしません。
5. 対象終了と保留処理の終息を確認した後にクリアします。ロック解放はその書込み確認後です。サーバー自体が終了する場合は、未完了の記録を残してOSのロックが外れることを許容します。

「書込み・確認」は、書込み、`FileStream.Flush(true)`、同じ保持ハンドルからの読戻しと意味検証までを候補とします。
別ハンドルを開く検証は `FileShare.None` と両立する前提を置けません。
途中失敗を成功として続行しないことが目的です。電源断に対する原子性をこの手順だけで保証するものではありません。

起動未完了の印から所有記録を完成させる間のクラッシュでは、完全な同一性がディスクに残らない可能性があります。
不正記録の開始拒否は誤終了を避けますが、追跡情報の完全な保存を保証しません。
生存中はメモリ上の情報と残存ファイルを保持し、診断の書込みも失敗し得ることを報告します。
この限界を許容できない場合は、J2の別ファイル案を再比較します。印を置くだけで追跡の問題を解消したとは扱いません。

## タイムアウトと遅延完了

推奨は、期限切れを応答待ちの終了とし、操作列の実行許可を同時に失効させる案です。
失効の判定と、次のCOM操作・状態更新の許可は同じ制御の下で決定します。
期限判定と完了が競合した場合も、完了を受理するか隔離するかを一度だけ決めます。

- 呼出し開始前に期限切れなら投入しません。既に開始した呼出しは止まったと仮定しません。
- 開始、保存、終了の各段の後で、次段の実行許可を確認します。Openが遅れて成功しても `ready` にしません。保存が遅れて成功してもCloseへ進みません。
- 遅延結果と例外は診断として回収します。タイムアウト応答やジョブの失敗を成功に書き換えません。元の呼出しだけでなく、通常列を継続しないことまで確認して実行枠を解放します。
- 回収後に `busy` が偽になっても `isolated` は維持します。破棄終了のための新しい安全確認は可能ですが、元の操作列は再開しません。
- 保留中の破棄終了は通常列の終息を待ちます。無応答なら、その終息を待つ前に、同一性確認と人の承認に基づくOS側の終了だけを許す案です。終了後の回収期限は現行の30秒を維持します。
- Excel終了と回収が済む前に新しいセッションを開始しません。遅れて戻った旧処理が新しいセッションの状態や記録を変更することを許しません。

起動・保存・終了の現行120秒は変更しません。
残存ExcelへのCOM照会は、開始処理の残り時間を超えない独立した上限30秒を初期候補とします。
これは実測値ではありません。残存Excelの自動後始末を採用する前に、S11・S12の該当ケースで応答時間と回収可能性を測り、採用値を評価します。初期PoCの前提にはしません。
照会が期限切れになっても、その照会自体が終了したとは扱いません。

## 承認待ちの安全条件3点の適用

| 安全条件 | 推奨する適用 | 境界・影響 |
| --- | --- | --- |
| Excelを残す場合の所有記録 | 終了未確認なら保持。新規起動の情報で上書きしない。次回開始でも同じ規則 | PID不明、記録破損、終了照会失敗は自動クリア不可。サーバー終了時は記録保持とOSロック解放を区別する |
| タイムアウト後の破棄終了 | `isolated` だけを通常実行中の終了禁止の例外にする。保留中の呼出しがあっても制御要求を受け付ける | `busy` の偽装解除や別STAでのCOM操作で代用しない。通常実行中の強制キャンセルAPIには広げない |
| Protected Viewの混入 | `ProtectedViewWindows.Count > 0` または確認不能なら自動終了を拒否 | 起動失敗後の後始末、通常・破棄終了、EOF、次回開始に共通適用。承認済み `force` の例外経路でも所有形式・同一性は省略不可 |

`force` をProtected Viewの拒否にも適用することは、R6の当該経路を実装する前に明示的に承認する対象です。
主ブック内の人の未保存編集や、照合直後の別ブックの混入を完全に防げるとは主張しません。

## T2で判断する点

以下は採用決定ではありません。推奨案の理由と、選ばなかった場合の差を示します。
T2では [初期経路と後続経路](#初期経路と後続経路) の初期分を確定し、後続分は未決として残します。

| ID・論点 | 比較案 | 推奨・理由 | 影響・承認後の反映先 |
| --- | --- | --- | --- |
| J1 起動途中の停止 | 所有確定後だけ記録する / 起動未完了の印を先行する | 印を先行する。所有情報完成前の停止を初回と区別して拒否できる | 「開始・終了は永続化しない」の例外が必要。公開状態は増やさず、復旧用の証拠だけ残す。[設計](../architecture.md#実行制御)と所有記録、Spike-0の起動停止ケースへ反映 |
| J2 記録の更新方式と保証範囲 | 同じ保持ハンドルで境界ごとに書込み・flush・検証 / 排他と記録を別ファイルに分け、記録を一時ファイルから置換 / 同一ファイルへ追記して履歴を解釈 | R1では単一ファイルと最小限の更新を推奨。既存設計を維持し、専用の履歴解釈を増やさない。ただし途中停止時の所有情報欠落と手動復旧を許容する判断が必要 | 完了記録、起動印、所有必須情報、版・空・部分書込みの拒否規則をT2で確定。完全な追跡保持が必須なら別ファイル案を比較し直す。別ファイル案は配置・排他と記録の関係を変更。追記案は破損した末尾の判定・世代管理を追加する |
| J3 遅延完了と隔離解除 | 遅延成功で通常列を継続 / 診断回収だけ行い隔離を維持 | 隔離維持。呼出し元が失敗と認識した後に保存・Close等を続けない | 開始・保存・終了の応答、ジョブ結果、内部継続の失効条件を[API](../api.md#共通規約)と設計へ反映 |
| J4 `isolated` の破棄終了 | 保留中はすべて拒否 / 制御経路だけ受付 | 後続の自動化候補として制御経路を受付。STAを塞ぐ呼出しがある状態でも承認後の終了と回収へ進める。初期は手動復旧 | 安全条件3点のうち2点目。R6で `session_end` の競合例外、`force` と人の確認、回収失敗の期待動作を確定。COMを介さない終了方式の実現性はS12で検証 |
| J5 次回開始と記録の保持・クリア | 終了未確認でも開始を優先 / 終了または確実な不在の確認後だけクリア。PID再利用時も自動クリアする / 人へ確認する | 未確認時は保持し、PID再利用時も人へ確認。記録異常と正常終了を混同しない | 安全条件の1点目。EOF、記録クリア失敗、同一性不一致、手動復旧を設計へ反映。人が復旧する対象、確認内容、記録を処理する順序をT2で決める |
| J6 Protected Viewと `force` | Workbooksだけを照合 / Protected Viewも確認し、不在を確認できなければ拒否 | 後者。Workbooksの列挙だけでは含まれないブックを除外できない | 安全条件の3点目。初期の拒否条件をT2で確定し、S11・PoC-1へケースを追加。人の明示承認を伴うforceの適用範囲はR6で確認 |
| J7 応答と期限 | 遷移専用の公開状態を追加 / 既存状態と `busy` を使う。残存照会を全体期限だけで待つ / 内側にも上限を置く | 公開状態を増やさず、後続の残存照会は最大30秒候補。照会に全体の120秒を使い切らせない | 初期の開始・終了中と記録失敗の状態・共通エラーへの対応はT2で確定。残存照会・終了後の回収失敗はR6で評価。数値の妥当性は未実測 |
