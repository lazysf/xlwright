# 0011: 作り直しで前提を失ったADRを退役させる

- Status: Accepted
- Supersedes: 0001, 0002

2026-11-02にユーザーが承認しました。
2026-11-02に、これまでの知見を参考にしつつ、0から作り直すことにしました。
作り直しの前のADR（0001〜0009）を1つずつ判定し、前提を失った0001と0002を退役させます。
ユーザーは、0001〜0009を一括で作り直しの前の判断として扱う案と比べて、1つずつの判定を選びました。

## 影響

- 0001: 判断が覆されました。要件の目標の3で、残った専用のExcelは手動復旧ではなく、次の開始で片付けることになったためです。排他と所有記録を1つのファイルで持つ形は、[設計](../architecture.md#実行時の状態と所有記録)が引き継ぎます。
- 0002: 対象が消えました。R1は旧いロードマップの段階で、新しいロードマップの段階0とプラグインによる配布に置き換わりました。CoreをMCPに依存させないことと、利用者のブック・設定・記録をサーバーのインストール先に置かないことは、[設計](../architecture.md)が引き継ぎます。

次のADRは、退役させません。

- 0004・0008: 新しい設計で採り直しました。0004の、セッションをサーバープロセス単位に保ち`session_id`を引数に取らない判断は、会話ごとにサーバーが1つ付くため、今も成り立ちます。0004の本文のうち、`.xlwright.lock`によるプロジェクト単位の排他と、EOFの規則による後始末は、設計に置き換わりました。0008は、NuGetの相互運用パッケージにライセンスが無いという理由が変わっていません。
- 0010: 作り直しの後の判断です。
- 0003: 開発版の入れ方が決まっていないため、今の開発の手順の根拠として残します。
- 0005・0007: ツールの契約を作り直していないため、今の実装の根拠として残します。
- 0006: アプリの指定の形を決めていないため、残します。
- 0009: 新しいサーバーの開発モードを決めていないため、今の実装の根拠として残します。
