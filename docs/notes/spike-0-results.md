## 対象と環境

T4の正常系実行手順を確認するため、L1の初回起動・変更・保存・通常終了を対象にしました。
次回開始を含むL1全体、L2〜L10、T5の故障注入前の確認全体の合格を示す記録ではありません。
ビルドSDKは10.0.403、実行対象は.NET 10・Windows x64です。
Excelの版は了承済みの登録情報16.0.20527.20088、64-bitを使います。
コードの位置と基準ブックは準備記録を参照してください。

使用したコマンドはリポジトリルートからの次のコマンドです。

```powershell
dotnet spikes/Spike0/bin/Release/net10.0-windows/Spike0.dll --excel
```

期待する結果は、検証用コピーの`Lifecycle!A2`を数値0から1へ変更して保存し、所有Excelの終了・完了記録・排他解放を確認できることです。
基準ブックは変更しません。

その実行に対応する既存の診断と保存ファイルを、Excelに接続せず確認しました。
実行時刻は2026-10-29 19:23:23〜19:23:29 JSTです。時刻は診断のUTC時刻から換算しています。
診断は`.xlwright/spike0/runs/022123e1dfbb4c22b0435e617803c7c7/diagnostics.jsonl`にあります。

| 観測対象 | 確認した結果 |
| --- | --- |
| 起動・所有確認 | `ownership.confirmed`、`start.ready`を記録。ready・busy=falseに到達 |

既存の業務用Excelとの同時利用や、異常条件での終了拒否は、この観測だけでは確認していません。

## エージェントによる実行：COM生成時のアクセス拒否

ユーザーの承認後、エージェントも同じコマンドを対話可能な端末で実行しました。
実行時刻は2026-10-29 19:24:30 JSTです。終了コードは1でした。
診断は`.xlwright/spike0/runs/b9367384268246e28306b51f491660b6/diagnostics.jsonl`にあります。

| 観測対象 | 確認した結果 |
| --- | --- |
| 開始前 | 所有記録はcompleted。OS照会でExcelプロセス0件 |
| 失敗境界 | generate-excelでUnauthorizedAccessException。COMクラスファクトリ取得が0x80070005（E_ACCESSDENIED）で失敗 |
| 状態 | isolated・busy=false。ExcelのPID等の所有同一性は取得していない |
| 所有記録 | startingを保持。completedへの整理や削除は行っていない |
| コピー | 基準ブックと同じSHA-256。Open・セル変更・保存・Close・Quitへ進んだ記録はない |
| 終了後 | 診断に記録されたコンソールPIDが不在であることと、観測時点のExcelプロセス0件を確認 |
| 後始末 | プロセス終了操作、設定変更、自動再送、所有記録の書換えは行っていない |

判定は、この実行環境ではCOM生成に失敗しました。Excel操作の成立性は判定できません。
排他取得後、起動印を確認した後に失敗しています。先行実行とのロック競合を示す結果ではありません。
サンドボックス等の実行権限の差は原因候補です。具体的な制約は未特定です。
この失敗だけで、構成上の撤退条件や別プロセス化を採用する判断はしません。

## 現在の状態と再開条件

T4はコード・資産・ビルドとユーザーによる初回正常系の確認まで完了です。
R1とT5は未完了です。ユーザーの成功とエージェントの失敗を合算して合格範囲を広げません。
現在の`.xlwright/spike0/.xlwright.lock`は、エージェント実行のstartingです。
次回実行はこの記録で拒否されます。作業領域を変えて開始拒否を回避しません。

再開には[手動復旧](../architecture.md#初期の手動復旧)の判断が必要です。
旧コンソール終了と残存可能性の確認根拠を保持します。
記録の整理を承認された範囲で行ってから、実行環境のアクセス拒否を切り分けます。
Excel操作は既存のユーザーの通常権限で行う前提を維持します。管理者権限や設定の緩和を解決策として採用していません。

結果記録にはログ全文、個人パス、実際のプロセスIDを転記していません。
